# 3 — 深度学习接口方案

> **定位**：为 DL 团队与前后端团队之间的接口对齐提供统一规范。本章由前后端团队撰写接口侧约束，DL 团队负责模型训练、推理引擎实现和 Python 侧接口开发。

---

## 1. 整体架构

```
┌──────────────────┐     HTTP/REST      ┌──────────────────┐
│  Spring Boot 后端 │ ◄────────────────► │  FastAPI (Python) │
│  (AI调度服务)      │                    │  DL 推理服务       │
│                   │                    │                   │
│  - 任务入队        │   POST /infer      │  - YOLOv11 推理   │
│  - 结果解析入库     │   ←──────────→    │  - 切片 + NMS     │
│  - 进度推送        │   GET /health      │  - TensorRT 加速  │
│                   │   POST /model/load │                   │
└──────────────────┘                    └──────────────────┘
```

**服务发现**：
- 车载端：FastAPI 与 Spring Boot 部署在同一台工控机，通过 `http://localhost:8001` 通信
- 地面端：FastAPI 部署在 GPU 服务器，通过内网 IP（如 `http://10.x.x.x:8001`）通信，或通过 Nginx 反向代理统一入口

## 2. 接口约定

### 2.1 健康检查

```
GET /api/dl/health
```

**响应**：
```json
{
  "status": "healthy",
  "loadedModels": [
    { "modelType": "onboard", "version": "yolov11s-v1.2", "loadedAt": "2026-05-13T10:00:00" },
    { "modelType": "ground", "version": "yolov11l-v1.3", "loadedAt": "2026-05-13T08:30:00" }
  ],
  "gpuAvailable": true,
  "gpuMemoryUsedMB": 8192,
  "gpuMemoryTotalMB": 24576
}
```

### 2.2 模型加载

```
POST /api/dl/model/load
Content-Type: application/json
```

**请求**：
```json
{
  "modelType": "onboard",
  "modelVersion": "yolov11s-v1.2",
  "forceReload": false
}
```

**响应**：
```json
{
  "success": true,
  "modelType": "onboard",
  "modelVersion": "yolov11s-v1.2",
  "loadTimeMs": 850,
  "message": "Model loaded successfully"
}
```

**约束**：加载延迟目标 ≤ 1s。若模型已在内存中且 `forceReload=false`，直接返回成功。

### 2.3 图像推理（核心接口）

```
POST /api/dl/infer
Content-Type: application/json
```

**请求**：
```json
{
  "imagePath": "onboard/202605130830_2号线_上行_鼓山_南门兜/鼓山-南门兜/K2249449_23/original/front_left.jpg",
  "modelType": "onboard",
  "confidenceThreshold": 0.5,
  "outputCoordType": "normalized",
  "extraParams": {
    "sliceSize": 1280,
    "sliceOverlap": 0.15,
    "highResRegions": [
      { "x": 0.2, "y": 0.1, "w": 0.3, "h": 0.15, "overlap": 0.25 }
    ]
  }
}
```

**请求参数说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `imagePath` | String | 是 | MinIO 上的图像相对路径，或本地绝对路径 |
| `modelType` | String | 是 | `"onboard"` 或 `"ground"` |
| `confidenceThreshold` | Double | 否 | 全局置信度阈值（0~1），默认从模型配置读取 |
| `outputCoordType` | String | 否 | `"normalized"`（归一化 0~1）或 `"pixel"`（像素坐标），默认 `"normalized"` |
| `extraParams.sliceSize` | Int | 否 | 切片尺寸（像素），车载默认 1024，地面默认 1280 |
| `extraParams.sliceOverlap` | Double | 否 | 切片重叠率，默认 0.15 |
| `extraParams.highResRegions` | Array | 否 | 关键区域坐标（归一化），这些区域使用更高重叠率 |

**响应**：
```json
{
  "success": true,
  "imagePath": "onboard/.../front_left.jpg",
  "processingTimeMs": 3200,
  "totalSlices": 48,
  "defects": [
    {
      "defectType": "nut_missing",
      "defectName": "螺母缺失",
      "confidence": 0.923,
      "box": { "x": 0.3421, "y": 0.5612, "w": 0.0123, "h": 0.0089 },
      "coordType": "normalized",
      "sourceSlice": { "row": 3, "col": 5 }
    },
    {
      "defectType": "split_pin_missing",
      "defectName": "开口销缺失",
      "confidence": 0.873,
      "box": { "x": 0.4512, "y": 0.6234, "w": 0.0087, "h": 0.0065 },
      "coordType": "normalized",
      "sourceSlice": { "row": 3, "col": 6 }
    }
  ]
}
```

**响应参数说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `defects[].defectType` | String | 缺陷类型编码（使用统一的缺陷字典） |
| `defects[].confidence` | Double | 置信度 0~1 |
| `defects[].box` | Object | 缺陷框（中心点+宽高） |
| `defects[].sourceSlice` | Object | 来源切片坐标（用于调试追溯） |

## 4. 非功能性 SLA

### 4.1 性能指标

| 指标 | 车载端（单 RTX 4090） | 地面端（3× RTX 4090） |
|------|----------------------|------------------------|
| 单张图像推理耗时 | ≤ 10s（含切片） | ≤ 200ms |
| 批量推理吞吐 | — | ≥ 5 张/秒 |
| 模型加载延迟 | ≤ 1s | ≤ 2s |
| 接口响应时间 (P99) | ≤ 15s | ≤ 2s |
| GPU 内存占用 | ≤ 16GB | ≤ 24GB × 3 |

### 4.2 准确率指标

| 指标 | 目标（当前采用） | 测量方式 |
|------|------|----------|
| 有效检出率 (Recall) | ≥ 90% | TP / (TP + FN) |
| 识别准确率 (Precision) | ≥ 90% | TP / (TP + FP) |
| 提报率 | ≤ 5% | 检出缺陷图片数 / 待检图片总数 |
| F1 Score | ≥ 0.90 | 2 × P × R / (P + R) |
| 识别速度（地面端） | ≥ 5 张/秒 | 批量推理吞吐 |

> ⚠️ **指标分歧待甲方书面确认**：源文档对精度要求不一致——
> - 《软件功能清单及各项参数标准（4）》4.2.2：检出准确率 **≥90%**，提报率 **≤5%**；
> - 《附件-1ver02》5.3.2：有效检出率 **≥95%**，提报率 **≤0.3%**，识别速度 ≥5 张/秒（1.5 节亦称准确率 95%）。
>
> **本方案当前以「参数标准文档（≥90% / ≤5%）」为验收基线**（较宽松、可达成），并将 95%/0.3% 列为优化目标。**最终验收口径需在合同/SRS 评审中由甲方书面锁定**，避免验收争议。DL 团队按锁定口径训练与评估。

## 5. 图像预处理约定

### 5.1 输入规格

| 参数 | 车载端 | 地面端 |
|------|--------|--------|
| 最大分辨率 | 1.27 亿像素（~13000×9800） | 同上 |
| 切片尺寸 | 1024×1024 | 1280×1280 |
| 切片重叠率 | 15% | 10%（普通区域）/ 25%（关键区域） |
| 输入格式 | JPEG / PNG | JPEG / PNG |
| 色彩空间 | RGB | RGB |

### 5.2 预处理管道（DL 侧实现）

```
原始图像 → 图像质量检查 → 按规则切片 → 切片缩放/归一化 → 送入模型
```

**质量检查项**（由 DL 侧实现）：
- 图像完整性校验（文件可读、非全黑/全白）
- 亮度异常检测（均值 < 10 或 > 245 标记为异常）
- 模糊检测（拉普拉斯方差 < 阈值标记为模糊）

质量不合格的图像正常返回结果，但附加 `qualityWarning` 标记，提醒后续人工复核注意。

## 6. 错误处理

### 6.1 错误响应格式

```json
{
  "success": false,
  "errorCode": "DL_GPU_OOM",
  "message": "GPU out of memory: required 12288MB, available 4096MB",
  "suggestion": "Try reducing batch size or slice size"
}
```

### 6.2 错误码列表

| 错误码 | HTTP 状态 | 说明 | 后端处理策略 |
|--------|-----------|------|-------------|
| `DL_MODEL_NOT_LOADED` | 503 | 模型未加载 | 自动调用 `/model/load` 重试，最多 2 次 |
| `DL_GPU_OOM` | 507 | GPU 显存不足 | 降低 batch size 后重试 |
| `DL_IMAGE_UNREADABLE` | 400 | 图像损坏/无法读取 | 标记为 `analysis_status='skipped'`，继续下一张 |
| `DL_INFERENCE_TIMEOUT` | 504 | 推理超时（单张 > 30s） | 记录错误，跳过此张 |
| `DL_INTERNAL_ERROR` | 500 | 内部异常 | 记录日志，重试 1 次 |

### 6.3 后端容错逻辑

```java
// 调用 DL 服务的容错包装
@Retryable(
    retryFor = { DlServiceException.class },
    maxAttempts = 3,
    backoff = @Backoff(delay = 1000, multiplier = 2)
)
public InferResponse infer(String imagePath) {
    try {
        return dlClient.infer(new InferRequest(imagePath, ...));
    } catch (DlOomException e) {
        // 自动降级：减小切片尺寸再请求
        return dlClient.infer(new InferRequest(imagePath, ..., 640));
    } catch (DlTimeoutException e) {
        // 超时：标记跳过
        markSkipped(imagePath, "DL inference timeout");
        return null;
    }
}
```

## 7. 模型版本管理

### 7.1 版本号规范

```
{基础模型}-{规模}-v{主版本}.{次版本}
示例：yolov11-s-v1.2  /  yolov11-l-v2.0
```

### 7.2 模型切换流程

```
1. DL 团队训练新版本 → 通过验证集评估
2. 新模型文件上传至 MinIO: models/{modelType}/{version}/
3. 更新模型版本配置（数据库 t_system_config）
4. 调用 POST /api/dl/model/load 加载新模型
5. 后端重启或热加载后使用新版本
```

### 7.3 向下兼容

- 接口路径不变（`POST /api/dl/infer`）
- 新增缺陷类型通过缺陷字典扩充，不影响已有类型的编码
- 旧版本模型可并行保留过渡期，通过 `modelVersion` 参数区分

## 9. 接口调测约定

前后端与 DL 服务的联调用一组固定的测试图像：

```
test-images/
├── normal/          # 无缺陷图像（5张，验证不误报）
├── defect/          # 有缺陷图像（含人工标注的真值，10张）
├── edge-case/       # 边界情况（强反光/模糊/遮挡，5张）
└── expected.json    # DL 预期输出结果（用于自动化对比）
```

联调通过标准：
- 20 张测试图像全部返回 HTTP 200
- 与 `expected.json` 中的缺陷类型、位置偏差不超过 5% 图像宽高
- 单张处理时间不超过 SLA 规定的上限
