## 4. Phase 2：逐类阈值校准 + 自适应双级阈值（P0）

### 4.1 背景与动机

分析报告指出：

- Stage 5 的全类别最高 F1 约 0.36，对应全局置信度约 0.196；
- 不同类别的 F1 峰值位置差异巨大（SVHTNL 约 0.35 vs SVHBNM 约 0.12）；
- Precision 曲线在置信度约 0.777 可达到 1.0，但此时 Recall 接近 0；
- **单一全局阈值完全不适用于当前 7 类差异化表现**。

因此必须实施逐类自适应阈值，而非简单全局搜索。

### 4.2 逐类阈值校准流程

1. 在 `calibration.yaml` 上为 OLD-S4、NEW-S4、NEW-S5 分别搜索逐类阈值；
2. 固定阈值后，在 `test.yaml` 上只评估一次；
3. 保存独立的 `thresholds.json`、`pr_curves.json` 和测试报告；
4. **禁止在同一个 split 上既搜索阈值又报告最终性能**。

执行命令：

```bash
python scripts/calibrate_thresholds.py \
  --model output/20260709_full_multisource/stage_5/weights/best.pt \
  --data data/eval_v20260713/calibration.yaml \
  --split val \
  --imgsz 1280 \
  --device 0 \
  --min-conf 0.001 \
  --iou 0.5 \
  --target-precision 0.80 \
  --target-recall 0.40 \
  --output output/eval_v20260713/new_stage5_calibration
```

目标 Precision=0.80、Recall=0.40 是阈值搜索目标，不是已经达到的承诺。如果某类不存在同时满足条件的阈值，必须输出其 Pareto 最优工作点，**禁止标记为达标**。

### 4.3 自适应双级阈值策略

校准完成后，为每类产出**两个工作点**而非一个：

| 工作点 | 用途 | 阈值策略 | 预期 Precision | 预期 Recall |
|--------|------|----------|:---:|:---:|
| **Auto-Report** | 自动提报（低 FP） | 高阈值，Pareto 前端 Precision≥0.80 点 | ≥ 0.80 | 较低 |
| **Human-Review** | 人工复核（高 Recall） | 低阈值，F2-score 最优点（Recall 权重 ×2） | 较低 | ≥ 0.80 |

`thresholds.json` 输出格式：

```json
{
  "VHBNM": {
    "auto_report":   { "conf": 0.72, "precision": 0.82, "recall": 0.55 },
    "human_review":  { "conf": 0.35, "precision": 0.31, "recall": 0.81 }
  },
  "SVHBNM": {
    "auto_report":   { "conf": 0.85, "precision": 0.80, "recall": 0.28 },
    "human_review":  { "conf": 0.42, "precision": 0.18, "recall": 0.62 }
  }
}
```

**使用方式**：推理时采用 `human_review` 阈值 → 高召回候选框 → 送入二级过滤器（Phase 7）→ 过滤器通过后使用 `auto_report` 阈值输出最终结果。

### 4.4 类别级阈值差异化建议

基于当前 Stage 5 每类指标，初步阈值建议（待 calibration 验证）：

| 类别 | Precision | Recall | 建议 auto_report 阈值 | 建议 human_review 阈值 | 策略 |
|------|:---:|:---:|:---:|:---:|------|
| SVHTNL | 0.474 | 0.911 | ~0.55 | ~0.25 | 高基线，直接可用 |
| VHBNL | 0.458 | 0.774 | ~0.55 | ~0.25 | 高基线，直接可用 |
| VHBNM | 0.250 | 0.857 | ~0.70 | ~0.30 | 提阈值压制 missing/loose 混淆 |
| SVHBNL | 0.205 | 0.493 | ~0.75 | ~0.35 | 提阈值 + 上下文辅助 |
| CBVPM | 0.179 | 0.578 | ~0.78 | ~0.38 | 提阈值压制背景混淆 |
| SVHBNM | 0.145 | 0.474 | ≥0.85 | ~0.45 | 极高阈值 + 二级过滤必需 |
| CBHPM | 0.101 | 0.577 | ≥0.85 | ~0.40 | 极高阈值 + 二级过滤必需 |

> 以上数值为基于当前 PR 曲线形态的粗略估计，实际阈值必须通过 calibration split 搜索确定。如果某类的 Precision 在任何阈值下都无法达到 auto_report 要求（≥0.80），该类走 `human_review` 通道 + 人工确认的流程，不做假达标。

## 6. Phase 3.5：Hard Normal 负样本生成（新增，P0）

> **本阶段为训练计划原有 Phase 3 和 Phase 4 之间新增**。
> 
> **背景**：当前场景增强（`generate_scene_augmentations.py`）只对**正样本**（有缺陷的 crop）做增强。但分析报告指出：正常螺栓边缘在特定光照下被模型高置信度误判为缺陷（VHBNL FP 平均置信度 0.646，最高 0.951），金属反光和阴影是主要 FP 来源（SVHBNM 占背景 FP 的 23%）。
>
> **思路**：对正常结构区域（无缺陷 crop）做极端场景增强，产物作为**无标签负样本**加入训练集。让模型被迫学习：即使在这个极端光照/对比度下，正常螺栓也不该被检测。

### 6.1 增强类型选择

与正样本增强不同，Hard Normal 增强应当更激进——模拟"最容易产生误检"的极端条件：

| 增强函数 | 强度 | 模拟场景 | 目标 FP 类型 |
|----------|------|----------|-------------|
| `white_balance_shift` | R×0.7-1.4, B×0.6-1.5 | 钠灯黄光 ↔ LED 冷白 ↔ 荧光绿偏 | 色彩偏移导致的边缘误检 |
| `tunnelize` | brightness×0.3-0.6 | 隧道暗区，阴影吞噬细节 | 暗区被误判为螺母缺失 |
| `sunlitize` | contrast×1.5-2.5 | 阳光直射金属表面高反差 | 反光区域误检 |
| `vibration_blur` | sigma 1.5-3.0 | 列车通过振动导致纹理模糊 | 模糊区域的伪影 |
| `motion_blur` | kernel 9-15 | 车辆运动模糊 | 方向性模糊产生的假边缘 |

#### 6.2.2 步骤 2：新增 Hard Normal 增强调度函数

在文件中新增以下函数（放在 `main()` 之前）：

```python
# ── Hard Normal augmentation scheduler ──────────────────────────────────────

_HN_AUG_SCHEDULES = {
    # (aug_fn, weight) — weights determine selection probability
    "medium": [
        ("tunnelize",       0.30),
        ("sunlitize",       0.25),
        ("white_balance",   0.25),
        ("vibration_blur",  0.15),
        ("motion_blur",     0.05),
    ],
    "high": [
        ("tunnelize",       0.30),
        ("sunlitize",       0.25),
        ("white_balance",   0.20),
        ("vibration_blur",  0.15),
        ("motion_blur",     0.10),
    ],
    "extreme": [
        ("tunnelize",       0.25),
        ("sunlitize",       0.25),
        ("white_balance",   0.20),
        ("vibration_blur",  0.15),
        ("motion_blur",     0.15),
    ],
}


def _apply_hard_normal_aug(
    img: "np.ndarray",
    intensity: str = "high",
) -> "np.ndarray":
    """Apply a single aggressive scene augmentation to a normal-structure crop.

    Unlike standard augmentation which balances multiple realistic conditions,
    this function picks ONE augmentation and applies it at higher intensity
    to simulate the worst-case scenarios that cause false positives.
    """
    schedule = _HN_AUG_SCHEDULES.get(intensity, _HN_AUG_SCHEDULES["high"])
    aug_names = [s[0] for s in schedule]
    weights = [s[1] for s in schedule]

    # Pick one augmentation based on weight distribution
    choice = random.choices(aug_names, weights=weights, k=1)[0]

    if choice == "tunnelize":
        # Aggressive: darker than standard (brightness 0.2-0.5 vs standard 0.3-0.7)
        brightness = random.uniform(0.2, 0.5)
        return tunnelize(img, brightness)

    elif choice == "sunlitize":
        # Aggressive: higher contrast (×1.8-3.0 vs standard ×1.2-1.8)
        contrast = random.uniform(1.8, 3.0)
        return sunlitize(img, contrast)

    elif choice == "white_balance":
        # Wide shift range to cover all tunnel light types
        r_gain = random.uniform(0.7, 1.4)
        b_gain = random.uniform(0.6, 1.5)
        return white_balance_shift(img, r_gain, b_gain)

    elif choice == "vibration_blur":
        # Stronger blur (sigma 1.5-3.0 vs standard 1.0-2.0)
        sigma = random.uniform(1.5, 3.0)
        kernel = random.choice([5, 7, 9])
        return vibration_blur(img, sigma, kernel)

    elif choice == "motion_blur":
        # Longer blur kernel (9-15 vs standard 5-11)
        kernel = random.choice([9, 11, 13, 15])
        angle = random.uniform(0, 360)
        return motion_blur(img, kernel, angle)

    return img  # fallback: return unchanged
```

#### 6.2.3 步骤 3：实现 Hard Normal 生成主逻辑

新增 `generate_hard_normals()` 函数：

```python
def generate_hard_normals(
    normal_images: List[Path],
    output_dir: Path,
    intensity: str = "high",
    n_per_region: int = 3,
    workers: int = 8,
) -> int:
    """Generate hard normal negative samples from normal-structure crops.

    Args:
        normal_images: List of paths to normal-structure crop images
                       (must have NO corresponding label file).
        output_dir: Output directory for augmented images.
        intensity: Augmentation intensity ("medium", "high", "extreme").
        n_per_region: Number of augmented variants per input image.
        workers: Number of parallel workers.

    Returns:
        Total number of generated hard normal images.
    """
    output_dir.mkdir(parents=True, exist_ok=True)
    tasks: List[Tuple[Path, int]] = []
    for img_path in normal_images:
        for variant_idx in range(n_per_region):
            tasks.append((img_path, variant_idx))

    generated = 0
    print(f"\nGenerating Hard Normal negatives ({intensity} intensity)...")
    print(f"  Source images : {len(normal_images)}")
    print(f"  Variants/image: {n_per_region}")
    print(f"  Target total  : {len(tasks)}")

    def _process_one(task: Tuple[Path, int]) -> Optional[Path]:
        img_path, variant_idx = task
        try:
            img = cv2.imread(str(img_path))
            if img is None or img.size == 0:
                return None

            augmented = _apply_hard_aug(img, intensity)

            stem = img_path.stem
            out_name = f"hn_{stem}_v{variant_idx}.jpg"
            out_path = output_dir / out_name
            cv2.imwrite(str(out_path), augmented, [cv2.IMWRITE_JPEG_QUALITY, 95])
            return out_path
        except Exception:
            return None

    with ThreadPoolExecutor(max_workers=workers) as pool:
        futures = [pool.submit(_process_one, t) for t in tasks]
        for f in tqdm(as_completed(futures), total=len(futures),
                       desc="Hard Normal", unit="img"):
            if f.result() is not None:
                generated += 1

    print(f"  Generated: {generated} hard normal images -> {output_dir}")
    return generated
```

#### 6.2.4 步骤 4：识别正常结构区域图片

Hard Normal 需要以**无标签的正常结构 crop** 为输入。新增一个辅助函数从 `subway_crops/train/` 中筛选：

```python
def _find_normal_images(
    images_dir: Path,
    labels_dir: Path,
    max_samples: int = 0,
) -> List[Path]:
    """Find images that have NO corresponding label file (negative samples).

    Args:
        images_dir: Directory containing training images.
        labels_dir: Directory containing YOLO-format label files.
        max_samples: Cap on number of normal images to return (0 = all).

    Returns:
        Sorted list of normal (unlabeled) image paths.
    """
    normal_images: List[Path] = []
    for img_file in sorted(images_dir.glob("*.jpg")):
        # Also match .png and .jpeg
        if img_file.suffix.lower() not in {".jpg", ".jpeg", ".png"}:
            continue
        label_file = labels_dir / f"{img_file.stem}.txt"
        if not label_file.exists():
            normal_images.append(img_file)

    if max_samples > 0 and len(normal_images) > max_samples:
        rng = random.Random(42)
        normal_images = rng.sample(normal_images, max_samples)

    return normal_images
```

```python
    hn_output = images_dir / "hard_normals"
    hn_output.mkdir(parents=True, exist_ok=True)

    generated = generate_hard_normals(
        normal_images=normal_imgs,
        output_dir=hn_output,
        intensity=args.hn_aug_intensity,
        n_per_region=args.hn_per_region,
        workers=args.workers,
    )

    print(f"\nDone. {generated} hard normal images saved to {hn_output}")
    print("These images have NO labels — YOLO treats them as negative samples.")
    print("Next: validate with --hard-normal flag confirmed, then retrain Stage 5.")
    return  # exit after hard normal generation
```

## 7. Phase 3.6：负样本（无缺陷图片）添加指南（新增）

### 7.1 当前负样本状态

`subway_crops` 已包含两类负样本：

| 来源 | 数量（估计） | 特点 |
|------|:---:|------|
| 结构化负样本 | ~20,000 | `generate_native_crops.py --negatives-per-image 25` 生成，覆盖正常结构区域 |
| 难负样本 (HN) | ~111 | `collect_hard_negatives.py` 收集的 Stage 4 FP crop，精准打击当前误检 |

### 7.2 负样本总量建议

基于 7 类 ~2,700 正样本 bbox，推荐负样本总量与比例如下：

| 参数 | 当前值 | 建议值 | 说明 |
|------|:---:|:---:|------|
| 正样本 : 负样本 比例 | ~1:7 | **1:10 ~ 1:15** | 负样本偏多有助于 Precision |
| 负样本总量 | ~20,000 | **25,000 ~ 40,000** | 覆盖更多正常结构模式 |
| Hard Normal 占比 | 0% | **5-10%** | 极端场景下正常结构的正确抑制 |
| HN (FP crop) 占比 | ~0.5% | **2-5%** | 定向打击当前误检模式 |

### 7.3 逐类负样本增量建议

基于当前 Stage 5 每类 Precision 和混淆矩阵中背景 FP 占比，计算各类别需要的额外负样本优先级：

| 类别 | Precision | 背景 FP 占比 | 当前负样本覆盖 | 建议追加负样本 | 优先级 | 采样重点 |
|------|:---:|:---:|:---:|:---:|:---:|------|
| **SVHBNM** | 0.145 | ~23% | 一般 | **+3,000 ~ 5,000** | P0 | 槽钢底座正常区域、边缘反光、焊接痕迹 |
| **CBHPM** | 0.101 | ~18% | 不足 | **+2,500 ~ 4,000** | P0 | 腕臂底座正常销钉、不同角度销钉头 |
| **SVHBNL** | 0.205 | ~16% | 一般 | **+2,000 ~ 3,000** | P1 | 槽钢正常螺母 + 垫片区域、阴影遮盖 |
| **CBVPM** | 0.179 | 背景 FP 明显 | 不足 | **+2,000 ~ 3,000** | P1 | 垂直销钉正常状态、不同视角 |
| **VHBNM** | 0.250 | VHBNL 混淆为主 | 一般 | **+1,500 ~ 2,500** | P1 | 正常底座螺栓、相邻正常螺母 |
| **VHBNL** | 0.458 | VHBNM 混淆为主 | 较好 | **+1,000 ~ 2,000** | P2 | 正常底座螺母 + 垫片特写 |
| **SVHTNL** | 0.474 | SVHBNM 混淆为主 | 较好 | **+1,000 ~ 1,500** | P2 | 正常槽钢上方螺母、多角度 |
| **总计** | — | — | — | **+13,000 ~ 21,000** | — | — |

> **推导方法**：以 Precision 最低的 SVHBNM 为例——当前 Precision 0.145，即每 100 个检测框约 85.5 个是 FP。混淆矩阵显示其中 ~23%（约 20 个）是背景被误判为 SVHBNM。要显著降低这 23%，需要在训练集中大量增加"容易与 SVHBNM 混淆的正常结构"作为负样本。按每个 FP 模式需要 100-200 个覆盖样本估算，SVHBNM 需要 3,000-5,000 个增量。其他类别类推。

### 7.4 负样本来源优先级

| 优先级 | 来源 | 采集方式 | 预期数量 | 适用类别 |
|:---:|------|------|:---:|------|
| 1 | 现有源图正常结构区域 | `generate_native_crops.py --negatives-per-image 40`（从 25 提高） | +5,000 | 全部 |
| 2 | 正常结构极端场景增强 | `generate_scene_augmentations.py --hard-normal`（本计划新增） | +2,000-3,000 | SVHBNM/CBHPM/VHBNM |
| 3 | Stage 4/5 模型 FP crop | `collect_hard_negatives.py --conf 0.15`（降低阈值收更多候选） | +300-500 | 全部，尤其 SVHBNM/CBHPM |
| 4 | 无缺陷源图全图 resize | 从 Defect_dataset 中挑选 0 缺陷的源图，resize 到 1280 加入 | +500-1,000 | CBVPM/SVHBNL |

### 7.5 负样本质量规则

| 规则 | 说明 |
|------|------|
| **无标签 = 负样本** | 图片放入 `train/images/` 但 `train/labels/` 中无同名 `.txt` |
| **禁止跨 split 泄漏** | 负样本源图必须来自 train split，不能从 calibration/test 取 |
| **分辨率一致性** | 负样本 crop 尺寸应与正样本一致（1280×1280），不混入不同分辨率 |
| **文件名唯一** | 负样本文件名不能与现有正样本重名（否则会被对应 label 覆盖） |
| **覆盖多样性** | 同一正常结构从不同光照/角度/偏移采样 3-5 个变体 |
| **避免无效样本** | 不采样纯色背景（天空）、完全模糊/过曝的无效区域 |

## 9. Phase 5：Stage 3 稳定性与能力消融（P1，增强版）

### 9.1 原则

- 保持 `amp=False`，先不重新引入已知高风险 AMP 路径；
- batch 保持 4，避免显存变量干扰；
- 每次只改变一个因素；
- 先跑 30 epoch 筛选，再把最优方案跑满；
- 每轮检查 loss finite，任何 NaN 立即停止并保存触发 batch 信息。

### 9.2 基础实验（原计划）

| 实验 | lr0 | 增强 | 其他 | 目的 |
|---|---:|---|---|---|
| S3-A | 2e-4 | 当前弱增强 | 当前稳定基线 | 对照 |
| S3-B | 3e-4 | 与 A 相同 | 其余不变 | 测试稳定范围内提高学习率 |
| S3-C | 2e-4 | 中等增强 | 其余不变 | 测试当前增强是否过弱 |

中等增强建议上限：

```yaml
hsv_s: 0.5
hsv_v: 0.5
degrees: 3.0
translate: 0.08
scale: 0.35
mosaic: 0.10
copy_paste: 0.0
auto_augment: none
amp: false
batch: 4
```

不在第一轮重新开启 copy-paste 或 auto-augment，因为两次 NaN 的触发因素尚未隔离。

### 9.3 新增实验：多尺度训练

| 实验 | multi_scale | 说明 |
|---|---|---|
| S3-D | 0.5 | 训练时在 640-1920 之间随机缩放，模型同时学习细节和上下文 |
| S3-E | 0.3 | 保守多尺度，640-1664 范围 |

```yaml
# S3-D 配置增量
multi_scale: 0.5   # 以 1280 为基准，上下浮动 50%（640-1920）
```

**预期收益**：小目标类别（SVHBNM/CBHPM）在高分辨率下有更多像素信息；松动类（VHBNL/SVHBNL）在低分辨率下能看到更大的结构上下文。代价是训练时间增加约 20%。

### 9.4 新增实验：类别加权 Loss

| 实验 | 加权方案 | 说明 |
|---|---|---|
| S3-F | SVHBNM×2.0, CBHPM×1.5, CBVPM×1.5, SVHBNL×1.3 | Precision 最低的 4 类加权 |
| S3-G | SVHBNM×2.5, CBHPM×2.0 | 仅最差 2 类极端加权 |

实现方式：修改 `subway_yolo/utils/loss.py` 中 loss 函数的 `pos_weight` 参数，按类别设置不同权重。需在 `data.yaml` 或训练参数中新增 `class_weights: [1.0, 1.0, 2.0, 1.3, 1.0, 1.5, 1.5]` 字段。

**注意**：YOLO 默认使用 VarifocalLoss（兼顾 IoU 和分类），直接加 class_weight 需要确认兼容性。若不兼容，改用 Focal Loss 调整方案（见 §9.5）。

### 9.5 新增实验：Focal Loss γ 调整

分析报告指出：模型对正常结构的误检**置信度很高**（VHBNL FP 平均置信度 0.646，最高 0.951），说明模型把"难分负样本"当成了"易分正样本"。

| 实验 | γ | 说明 |
|---|---|---|
| S3-H | 2.5 | 比默认 γ≈1.5 更高，惩罚"自信但错误"的预测 |
| S3-I | 3.0 | 极端 γ，最激进的易分样本降权 |

实现方式：修改 `subway_yolo/utils/loss.py` 中 `VarifocalLoss.__init__()` 的 `gamma` 参数，或通过训练配置新增 `fl_gamma: 2.5` 字段。

**风险**：γ 过高会导致难分正样本（真正的小缺陷）也被降权，可能降低 Recall。必须通过 calibration split 监控。

### 9.6 筛选与停止条件

30 epoch 筛选时满足任一以下条件即淘汰：

- 出现 NaN/Inf；
- 固定 calibration 集 mAP50-95 低于 S3-A 超过 0.005；
- 任一 P0 类 Recall 下降超过 0.05；
- 验证损失连续 10 轮恶化且 mAP50-95 无新高。

最优方案跑满 60-80 epoch 后，至少使用 seed 0/1/2 复验。单个 80 epoch Stage 3 约 15.4 GPU 小时；三个种子约 46 GPU 小时。

### 9.7 通过条件

| 指标 | 要求 |
|---|---:|
| test mAP50-95 | 比当前 NEW-S3 提升 >= 0.010 |
| test P@R=0.60 | 提升 >= 0.05 |
| SVHBNM AP50 | 不低于当前 |
| NaN | 0 次 |
| 三种子相对标准差 | 主要指标 < 5% |

### 9.8 Phase 5 实验优先级与预算

| 优先级 | 实验 | 预计 GPU 时间 (30 epoch) | 说明 |
|:---:|------|:---:|------|
| P0 | S3-D (multi_scale=0.5) | ~2 h | 最高性价比，同时改善细节和上下文 |
| P0 | S3-B (lr0=3e-4) | ~2 h | 验证当前 lr 是否过于保守 |
| P1 | S3-H (fl_gamma=2.5) | ~2 h | 降低高置信 FP |
| P1 | S3-F (class_weights) | ~2 h | 针对性改善最差类 |
| P2 | S3-C (中等增强) | ~2 h | 验证增强强度影响 |
| P2 | S3-E/I/G | ~6 h | 多尺度/focal/权重的细化方案 |

## 11. Phase 7：二级状态过滤器（P2）

如果阈值校准和受控 Stage 5 后 Precision 仍低于可用水平，进入级联系统。

### 11.1 先做轻量基线

| 模型 | 任务 | 作用 |
|---|---|---|
| MobileNetV3-Small | normal vs defect | 低成本部署基线 |
| ResNet18 | normal vs defect | 稳定对照 |
| Tiny Transformer/MobileViT | 状态分类 | 仅在 CNN 上下文不足时使用 |

不要直接假设 Transformer 必然更好。先用相同数据比较 CNN 与 Transformer，再决定复杂度。

### 11.2 数据构建

输入使用 YOLO box 的 1.2x、2.0x 上下文 crop，标签建议分两级：

```text
Level 1: normal / defect
Level 2: missing / loose / other anomaly
```

数据必须按源图划分，禁止同一目标的不同尺度 crop 跨 train/test。

### 11.3 验收

| 指标 | 目标 |
|---|---:|
| defect recall | >= 0.95 |
| FP rejection rate | >= 0.50 |
| Cascade Recall 损失 | <= 0.05 |
| Cascade Precision 提升 | >= 0.10 |
| 单 crop 推理延迟 | 记录 P50/P95 |

重点对 VHBNM/VHBNL 和 SVHBNM/SVHTNL 做状态混淆评估。

## 14. 总停止条件

满足任一条件时停止当前训练分支：

1. 出现 NaN/Inf；
2. 30 epoch 筛选未比固定基线提高 mAP50-95 至少 0.005；
3. 提高 Precision 导致 Recall 下降超过 0.05；
4. P0 类别中任一 Recall 下降超过 0.05；
5. FP 审计发现漏标超过 5% 或同源泄漏；
6. Stage 5 相对 Stage 4 的 mAP50-95 下降超过 0.005；
7. 三种子主要指标相对标准差超过 5%，需要先解决不稳定性；
8. 二级过滤器的 Recall 损失超过 0.05。

最终主线为：

```text
冻结评估口径
  -> 四权重同测
  -> 阈值校准 + 双级工作点
  -> FP/HN 审计
  -> Hard Normal 负样本生成 + 负样本增量采集   ← 新增
  -> Stage 2 数据消融
  -> Stage 3 多尺度 + focal + 类别加权消融     ← 增强
  -> Stage 4/5 配对验证
  -> 二级状态过滤器
```

这条路线能回答每一次性能变化来自哪里，并避免再次用单次峰值或不同数据版本做不可比结论。
