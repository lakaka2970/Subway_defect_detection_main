# 地铁缺陷检测 7.18 下一步计划

> **制定日期**：2026-07-18  
> **基线权重**：`output/7.14训练结果/selected/stage4_best.pt`  
> **计划目标**：优先降低结构性误报并补足弱类召回，建立可复现、可门禁的下一轮训练闭环  
> **原则**：数据和评估先于大训练；小实验通过门禁后才进入完整训练

---

## 0. 核心决策

下一轮不再继续大范围搜索学习率、multi-scale、class weight 或 focal gamma。本轮已经证明这些变体均未超过 `s3_a`，当前主要瓶颈是**结构性强负样本不足、弱类样本不足、状态定义含糊和单阶段 detector 的能力边界**。

本计划分为四条主线：

```text
P0 数据与评估治理
  → P0 强负样本闭环重建
  → P1 Stage 4 小步对照实验
  → P1 二阶段状态分类器 PoC
  → 通过门禁后完整训练与最终冻结测试
```

### 本轮明确停止的事项

- 停止 `s3_b` 更高学习率路线；
- 停止 `s3_d` multi-scale 路线；
- 暂停仅靠 class weight 或更高 focal gamma 的弱类优化；
- 不再用 test 集反复选超参数；
- 不把当前 Stage 5 HN 作为默认主模型；
- 不在 HN 仍只有个位数时重复 Stage 5 完整训练。

## 1. 目标与硬门禁

### 1.1 下一轮阶段目标

目标分为“研发晋级线”和“生产验收线”。下一轮先达到研发晋级线，不把一次训练直接包装成生产达标。

| 指标 | 当前 Stage 4 | 下一轮研发晋级线 | 长期生产目标 |
|---|---:|---:|---:|
| test mAP50 | 0.3750 | ≥0.3850，或在 FP 明显下降时不低于 0.3712 | 非唯一验收指标 |
| test mAP50-95 | 0.2119 | ≥0.2180，或不低于 0.2077 | 持续提升 |
| F2 工作点 FP | 676 | ≤575（至少 -15%） | 按业务提报率约束 |
| F2 工作点 TP | 211 | ≥207（下降不超过 2%） | Recall≥0.90 |
| 原生 Recall | 0.6034 | ≥0.60 | ≥0.90 |
| 源级 Precision 95% CI 下界 | 0.1605 | ≥0.18 | 需结合业务阈值 |
| SVHBNM FP | 345 | ≤276（-20%） | 持续下降 |
| SVHBNL test GT | 21 | 扩充至 ≥50 个独立源 GT | ≥100 更稳妥 |

说明：若 mAP 变化小，但 FP 降低 ≥15%、TP 保持率 ≥98%，仍允许晋级，因为当前首要业务痛点是误报。

### 1.2 校准门禁

对每个候选模型只在 calibration 上确定阈值，再一次性运行 test：

- 自动提报线：优先 P≥0.90；若无法达到，必须同时报告该阈值下 Recall，不允许只报告 Precision。
- 人工复核线：优先 R≥0.85，并报告每 1,000 crops FP。
- 所有阈值用 source-group bootstrap 给出 95% CI。
- 生产验收要求每类 P≥0.90 且 R≥0.90；任何单独达标不得写成整类达标。

## 2. Phase A：数据与评估治理（P0，1–2 天）

### A1. 冻结当前基线与测试协议

执行内容：

1. 将 `selected/stage4_best.pt` 的 SHA256、文件大小、模型参数和 Ultralytics 版本写入新的 run manifest。
2. 冻结 `train/calibration/test/hn_mining` 的 source_id 清单。
3. 新一轮禁止修改现有 test；新增数据只能进入 `candidate_pool`，审核后在下一版本整体重切。
4. 固定评估参数：imgsz=1280、IoU=0.5、min_conf=0.001、同一 NMS 参数。
5. 统一输出原生指标、F2 工作点、固定 Recall 下 Precision、固定 Precision 下 Recall、每 1,000 crops FP/FN 和源级 CI。

**完成门禁**：数据 manifest 哈希一致；所有 split 源组交集为 0；同一权重重复评估的指标差异 <1e-6。

### A2. 标签与错误样本审计

优先类别：SVHBNM → SVHBNL → SVHTNL → CBVPM → VHBNM/VHBNL。

需要抽取：

- Stage 4 test 每类全部 TP、FP、FN；
- SVHBNM 345 个 FP 全量；
- SVHBNL 21 个 GT 全量；
- SVHTNL 94 个 FP 全量；
- 随机抽取每类至少 100 个 TN；
- 所有 empty-label crop。

为每个错误样本增加字段：

```text
source_id, crop_id, predicted_class, gt_class, confidence,
error_type, component_type, state_label, lighting, blur,
occlusion, boundary_object, annotation_action, reviewer
```

错误类型统一为：

1. `texture_fp`：反光、污渍、加工纹理；
2. `structure_fp`：正常螺母、孔位、边缘等同构部件；
3. `class_confusion`：七类之间互相混淆；
4. `localization_error`：类别正确但 IoU 不足；
5. `missing_annotation`：疑似漏标；
6. `ambiguous_state`：正常/松动/缺失边界不清；
7. `true_fn`：确实漏检。

**完成门禁**：双人复核至少 20% 样本；类别/状态一致率 ≥90%；漏标和争议样本从训练集隔离，不直接作为负样本。

### A3. 修复复现与恢复机制

需要解决：

- `Checkpoint/CSV mismatch: checkpoint=0, csv=60`；
- partial/invalid AMP 运行不能自动进入候选池；
- dirty worktree 的代码状态必须由 commit + patch + config + pip freeze 完整记录；
- NMS time-limit warning 不应仅靠 override，需记录实际耗时和被截断批次。

**完成门禁**：从 epoch checkpoint 恢复 2 个 epoch，CSV 连续、epoch 连续、权重可加载，审计 gate 自动通过。

## 3. Phase B：重建强负样本闭环（P0，2–3 天）

### B1. HN 采集漏斗

本轮 `collected=2, mixed=2` 不足以支持训练。下一轮对 Stage 4 在冻结 train-derived HN 子集进行多阈值采集：

| 参数 | 建议值 |
|---|---|
| conf | 0.03、0.05、0.10、0.20 四档 |
| IoU 判 FP 阈值 | 0.10 与 0.30 两档 |
| 单源每类上限 | 5–10，防止同源重复 |
| 去重 | perceptual hash + 同源同类 IoU 去重 |
| 裁剪上下文 | 目标框 1.5×、2.0× 两档 |
| 来源 | 仅 train/hn_mining，不接触 calibration/test |

必须输出漏斗统计：

```text
raw detections
→ unmatched detections
→ confidence filtered
→ source-balanced
→ perceptual deduplicated
→ human accepted
→ mixed into train
```

**完成门禁**：至少 500 个经人工确认的结构性 HN；每个重点类至少 100 个，若不足则不启动完整 Stage 5。

### B2. HN 质量而非数量优先

HN 配额建议：

| 类别 | 首轮目标 | 原因 |
|---|---:|---|
| SVHBNM | 300 | 当前贡献 51% FP |
| SVHTNL | 150 | 结构/反光混淆高 |
| VHBNM | 100 | Recall 已高，适合专攻 Precision |
| VHBNL | 100 | 接近可用，可通过负样本改善 |
| CBVPM | 100 | 召回与 Precision 均中等 |
| SVHBNL | 100 | 数量少，需严格审核避免错负样本 |
| CBHPM | 50 | 已是强类，防止过度抑制 |

同一源组、相邻帧或近重复图不能占据大部分 HN；每类有效源组至少 30 个。

### B3. 训练集混入比例小试

先做三组 3–5 epoch 小实验，所有其他配置相同：

| 组别 | HN:正样本图 | 学习率 | 冻结 | 目的 |
|---|---:|---:|---|---|
| H0 control | 0 | 5e-6 | 0–9 | 随机波动基线 |
| H1 | 0.5:1 | 5e-6 | 0–9 | 温和抑制 FP |
| H2 | 1:1 | 5e-6 | 0–9 | 检查更强 HN 信号 |

如三组差异接近随机噪声，再追加“冻结 0–7”而不是先升高 HN 数量。不要同时改学习率、冻结层和 HN 比例。

**晋级门禁**：calibration 上 FP 相对 control 降低 ≥10%，TP 保持率 ≥98%，mAP50-95 下降不超过 1%。

## 4. Phase C：Stage 4 小步微调实验（P1，1–2 天）

Stage 4 当前是最优模型，优先做低成本局部验证。

### C1. 严格单变量实验

| 实验 | 改动 | epoch | 预期 |
|---|---|---:|---|
| S4-C | 原 Stage 4 重跑 | 5 | 获得随机波动范围 |
| S4-L | lr 1e-5 → 5e-6 | 5 | 减少召回损失 |
| S4-U | freeze 0–9 → 0–7 | 5 | 允许更深层适应状态特征 |
| S4-A | 保持配置，仅将 translate 0.02 → 0 | 5 | 判断增强是否伤害精细状态 |

每个实验至少 seed0/seed1；如果资源有限，先运行 3 epoch screen，只对满足门禁者跑到 5 epoch。

### C2. 停止规则

- calibration mAP50-95 连续 2 epoch 无提升即停止；
- val box loss 相对最佳点上升 >5% 且 FP 未下降即停止；
- 任一重点类 Recall 绝对下降 >5 个百分点即否决；
- 训练日志出现 NaN、不可恢复 OOM 或 NMS 截断即不进入模型比较。

## 5. Phase D：二阶段状态分类器 PoC（P1，3–5 天）

### 5.1 为什么现在需要二阶段

当前 CBHPM AP50=0.9529，而螺栓/螺母状态类普遍较差，表明 YOLO 能找到部分部件，但难以可靠判断“正常、松动、缺失、边界状态”。因此建议让 Stage 4 负责 proposal，轻量分类器负责状态判别。

### 5.2 首轮范围

先做两个 PoC，不一次覆盖七类：

1. **CBHPM 二分类**：missing vs normal，用作流程和上限验证；
2. **VHBNM/VHBNL 状态分类**：normal / missing / loose / ambiguous；
3. SVHBNM/SVHBNL 在标签审计完成后再加入，避免把定义噪声带入分类器。

### 5.3 数据构建

分类器输入使用 YOLO proposal 周围 1.5×–2.0× 上下文，按 source_id 拆分，禁止相邻 crop 跨 split。每个状态至少：

- train 300 个独立或近独立样本；
- calibration 80 个；
- test 100 个；
- strong normal 不少于正样本的 1–2 倍；
- ambiguous 单独成类，不强迫并入正常或缺陷。

### 5.4 模型与门禁

先使用轻量 CNN/MobileViT 级别模型，不追求复杂架构。比较：

- detector only；
- hard gate：`det_conf × cls_prob`；
- 两阈值 cascade：自动提报/人工复核。

**PoC 成功线**：在 detector Recall 保持率 ≥98% 的前提下，目标类 FP 降低 ≥30%；端到端额外推理耗时 <20%。若不达标，先回到数据定义，不升级模型复杂度。

## 6. Phase E：弱类数据补强（P1，持续 1–2 周）

### 6.1 数量目标

| 类别 | 当前 train 框 | 第一阶段目标 | 重点样本 |
|---|---:|---:|---|
| SVHBNL | 47 | ≥150 | 松动程度、不同角度、同部件正常对照 |
| SVHTNL | 94 | ≥200 | 金属反光、孔位、加工纹理 |
| CBVPM | 121 | ≥200 | 遮挡、方向变化、低对比度 |
| VHBNL | 90 | ≥180 | 正常/松动边界对 |
| SVHBNM | 286 | 数量暂不优先 | 重点提升标签与负样本质量 |

### 6.2 采集原则

- 以独立线路、区间、设备编号和拍摄批次增加多样性；
- 同一源的相邻帧不计为独立增量；
- 每个缺陷样本尽量配同部件/同角度正常对照；
- 边界样本必须由两名标注者给出状态与置信等级；
- 合成增强仅作补充，不能替代真实状态样本。

## 7. Phase F：完整训练与最终评估（通过前置门禁后，2–3 天）

### 7.1 推荐训练顺序

```text
Stage 2 s2_a best
  → Stage 3 s3_a（固定 imgsz=1280、lr0=2e-4、弱增强）
  → 最优 Stage 4 单变量配置
  → 合格 HN 小比例微调
  → calibration 校准
  → test 一次性冻结评估
```

### 7.2 稳定性要求

- 至少 3 个真正只改变 seed 的完整运行；
- batch、AMP、数据、配置和代码 commit 必须一致；
- 报告均值、标准差、最差 seed，不只报告最好 seed；
- RSD≤3% 且最差 seed 仍满足研发门禁，方可晋级。

### 7.3 候选选择评分

建议使用业务加权评分，而不是单看 mAP：

```text
score = 0.30 × normalized(mAP50-95)
      + 0.20 × normalized(mAP50)
      + 0.25 × normalized(TP retention)
      + 0.25 × normalized(FP reduction)
```

同时设置否决项：任一严重类 Recall 下降 >5 个百分点、测试泄漏、NaN、评估不完整，直接淘汰。

## 8. 推理与部署基准（P2，与数据工作并行）

当前训练结果没有完成最终 127MP 端到端性能验收。需要对 Stage 4 和 cascade PoC 测试：

- 单张 127MP 图像切片、推理、NMS、坐标回映射总耗时；
- 峰值 GPU 显存；
- 单卡与双卡吞吐；
- proposal 数量对二阶段耗时的影响；
- FP 去重和跨 crop 合并后的最终提报率。

每个场景 warmup 20 次、正式测试至少 100 张，报告 P50/P95/P99 延迟。精度和速度必须使用同一导出模型与同一阈值配置。

## 11. 风险与应对

| 风险 | 触发信号 | 应对 |
|---|---|---|
| HN 再次采集过少 | 人工审核后 <500 | 放宽采集阈值、扩大 train-derived 源、检查去重漏斗，不启动 Stage 5 |
| HN 抑制 TP | TP 保持率 <98% | 降低 HN 比例或改为二阶段分类训练 |
| 弱类指标剧烈波动 | 不同 seed R 差 >10pp | 先补独立源样本，不继续调参 |
| calibration 到 test 阈值漂移 | P 或 R 下降 >10pp | 扩大 calibration、按场景分层、报告 CI |
| cascade 速度过慢 | 端到端耗时增加 >20% | 限制 proposal 数、批量分类、轻量模型/ONNX/TensorRT |
| 恢复训练不一致 | checkpoint/CSV mismatch | 阻断门禁，修复后从干净 run 重启 |

## 12. 最终执行优先级

### 必须立即执行（P0）

1. 冻结协议与修复复现/恢复链；
2. 全量审计 SVHBNM FP 和 SVHBNL GT；
3. 重建 HN 采集漏斗，先达到 ≥500 个审核通过 HN；
4. 用 H0/H1/H2 做严格 control 对照。

### 通过 P0 后执行（P1）

1. Stage 4 小步单变量实验；
2. CBHPM 与 VHBNM/VHBNL 二阶段分类 PoC；
3. SVHBNL、SVHTNL、CBVPM 独立源补数；
4. 三种子完整训练。

### 可并行但不阻塞主线（P2）

1. 127MP 端到端速度与显存测试；
2. 推理导出与部署优化；
3. FP 回流和主动学习界面。

本计划的核心不是“再训一次”，而是让每一次训练都有清晰假设、对照组、数据门禁和停止条件。只有当 HN 质量、弱类样本和状态判别能力得到实质改善，下一轮完整训练才有较高成功概率。
