关键观察：
- **CBVPM 暴涨**（+0.403 AP50）：Copy-Paste 增强直接受益者，说明数据增强对特征明显类非常有效
- **CBHPM 大跌**（-0.259 AP50）：7.24 数据集中该类的 P 从 0.761 降到 0.456，可能是新 val 集包含更多困难样本
- **斜拉线三类均改善**（+0.053~0.057）：数据治理对弱类有实质性帮助
- **VHBNL 退化**：Recall 从 0.872 降到 0.333，需要检查 val 集质量

### 1.3 性能分析关键结论

1. **数据治理对弱类有效**：斜拉线三类（SVHBNM/SVHBNL/SVHTNL）AP50 合计改善约 0.164，证明更多样本 + 更好平衡 + Copy-Paste 是正确方向。

2. **但改善幅度远不足以达到验收**：即使改善后，斜拉线三类 Precision 仍在 0.12-0.15，Recall 在 0.48-0.67。按当前改善速度线性外推，需要再改善 5-6 倍数据/架构才能触及 0.90/0.90。

3. **Vanilla YOLO11s 已触碰能力边界**：在做了大量数据优化后，mAP50 从 0.375 仅提升到 0.389（+3.7%），Precision 和 Recall 甚至下降。这说明当前架构的单阶段检测范式已无法充分利用更好的数据。

4. **Stage 4 退化说明微调策略需重新设计**：7.14 中 Stage 4（freeze 0-9, lr=1e-5, 零增强）提升 mAP50 4.7%。7.24 中同样策略反而下降 2.6%。新数据的分布不同，微调策略不能照搬。

## 2. 当前模型的核心瓶颈诊断

### 2.1 瓶颈一：单阶段 Detector 承担了不该承担的状态判别任务（P0）

**证据**：
- CBHPM 在 7.14 中 AP50=0.953（接近可用），但 7.24 中降至 0.694。该类的视觉特征（接触线硬点）主要是纹理异常，detector 可以学会。而 VHBNM/VHBNL 需要判断"螺母是否缺失/松动"，这是细粒度状态分类问题。
- SVHBNM 的 Recall=0.620 说明 detector 能找到斜拉线硬点区域，但 Precision=0.149 说明它无法区分"正常硬点"和"缺陷硬点"。
- 7.14 分析报告中双阈值校准显示：自动提报（高阈值）下 Recall 仅 0.267，人工复核（低阈值）下 Precision 仅 0.206，说明正负样本的置信度分布严重重叠。

**判断**：单阶段 YOLO 可以学会"找到部件"，但无法可靠学会"判断部件状态"。必须引入二阶段状态判别。

### 2.2 瓶颈二：EMA-SimAM 定制架构从未被使用（P0）

**证据**：
- `subway_defect/models/` 目录有 3 个定制架构 YAML，专为接触网缺陷检测设计
- EMA（ICASSP 2023）多尺度注意力适合部件级特征增强
- SimAM（ICML 2021）零参数 3D 注意力适合无额外计算开销的显著性增强
- P2 检测头专为极小目标（VHBNL 最小框 0.44% 面积）设计
- 两次完整训练（7.14 和 7.24）均使用 `yolo11s.pt`（vanilla COCO 预训练），从未使用定制架构
- SPECIFICATION.md 第 8 节明确将 EMA-SimAM 列为模型规格的组成部分

**判断**：这是当前最大的未兑现潜力。保守估计 EMA-SimAM 可带来 5-15% 的 mAP 提升，尤其是对弱类和状态判别类。

### 2.3 瓶颈三：二阶段分类器代码就绪但从未训练（P0）

**证据**：
- `subway_defect/classifier/` 包含完整的 MobileNetV3-small 分类器实现
- `scripts/prepare_classifier_data.py` 和 `scripts/train_state_classifier.py` 已写好
- 7.14 A2 审计已产出 90 个严格 HN 候选和 68 个有效漏检，可用于分类器训练
- 7.18 计划 Phase D 的目标是"FP 降低 ≥30%"，这个目标在 7.14 条件下是可实现的
- 至今未执行任何分类器训练

**判断**：二阶段分类器是解决 Precision 瓶颈的最直接手段。先对 CBHPM（特征最明显）做 PoC 验证管道，再推广到 VHBNM/VHBNL。

### 2.4 瓶颈四：弱类的独立源组样本仍然不足（P1）

**证据**：
- 7.24 数据集通过 minority×3 增加了少数类的 crop 数量，但增加的是同源图像的变体（不同 crop 位置），不是独立源组
- SVHBNL train 原始框仍仅 209 个（来自有限源组），test 仅 21 个 GT
- A2 审计发现 SVHBNL test 仅 21 个 GT，单个样本可造成约 4.8pp 的召回波动
- 缺乏同部件/同角度的"正常 vs 缺陷"对照对，导致模型无法学到区分性特征

**判断**：数据增强（Copy-Paste、场景增强）可以缓解但不能替代独立源组样本。SVHBNL 和 SVHTNL 需要从新线路/区间采集至少 50-100 个独立源 GT。

### 2.5 瓶颈五：Stage 4 微调策略在新数据上失效（P1）

**证据**：
- 7.14: Stage 3 (0.358) → Stage 4 (0.375) = +4.7%
- 7.24: Stage 3 (0.389) → Stage 4 (0.379) = -2.6%
- 7.24 新数据集的正负比例（55% vs 90%）、增强程度、类别分布均与 7.14 显著不同
- freeze 0-9 + lr=1e-5 + 零增强的策略假定"backbone 特征已足够好，只需微调 head"，但在新数据上可能不成立

**判断**：需要重新搜索 Stage 4 的最优配置（freeze 范围、学习率、增强程度），不能照搬 7.14 的结论。

## 3. 战略方向：从"单阶段检测"到"检测 + 状态判别 + 定制架构"

### 3.1 为什么继续调参不会成功

从 7.8→7.14→7.24 三次完整训练的演进轨迹来看：

| 版本 | 模型 | 核心策略 | mAP50 | P | R |
|---|---|---|---|---|---|
| 7.8 (远端) | YOLO11m | 多源预训练 + HN | 0.350 | 0.260 | 0.666 |
| 7.14 (本地) | YOLO11s | 源隔离 + 受控实验 + HN | 0.375 | 0.328 | 0.603 |
| 7.24 (本地) | YOLO11s | 数据治理 + 增强扩充 | 0.389 | 0.302 | 0.573 |

三次迭代的 mAP50 提升幅度分别为 +0.025（7.8→7.14）和 +0.014（7.14→7.24），边际收益递减明显。同时 Precision（0.260→0.328→0.302）和 Recall（0.666→0.603→0.573）在波动中无方向性改善。

**继续在 vanilla YOLO11s 上做超参数搜索、数据增强或 HN 挖掘，预计 mAP50 上限在 0.40-0.42 左右，无法触及 0.90 Precision 和 0.90 Recall 的验收线。**

## 4. Phase A：EMA-SimAM 架构切换与基线重建（P0，2-3 天）

### 4.1 为什么必须现在切换

- EMA-SimAM 架构是 SPECIFICATION.md 第 8 节定义的正式模型规格，是项目设计的一部分
- 两次训练均未使用，相当于一直在用"简化版"跑实验
- EMA 多尺度注意力可以增强不同尺度部件的特征表达，直接受益于 SVHBNM（大框 5.6%）和 VHBNL（小框 2.5%）的尺度差异
- SimAM 零参数 3D 注意力可以在不增加推理耗时的情况下提升显著性判别，对"正常 vs 缺陷"状态区分可能有直接帮助
- P2 检测头变体可以专门解决极小目标（0.44% 面积）的检测问题

### 4.2 执行内容

#### A1. 固定 EMA-SimAM 架构的训练配置

1. 以 `subway_defect/models/yolo11s-EMA-SimAM.yaml` 为基础
2. 创建对应的预训练 Stage 配置（Stage 1A/1B 使用 EMA-SimAM 架构 + mixed_pretrain 数据）
3. 确认 `subway_yolo/nn/Extramodule/` 的模块注册正常工作
4. 运行架构验证：`python -c "from subway_yolo import YOLO; m = YOLO('subway_defect/models/yolo11s-EMA-SimAM.yaml'); print(m)"`

**完成门禁**：模型成功构建，EMA/SimAM 模块正确插入检测头，参数量约 9.5M（与 vanilla YOLO11s 接近）。

#### A2. 运行 EMA-SimAM 完整五阶段训练

使用 7.24 已构建的数据集（`data/subway_crops/` + `data/subway_crops_1024/`），仅切换模型架构：

```bash
python scripts/train_pipeline.py --stages 1a 1b 2 3 4 \
    --model yolo11s-EMA-SimAM --device 0 --workers 4
```

训练配置沿用 7.24 已验证的最优参数（batch=32/16, workers=4, amp=true）。

**完成门禁**：
- 五阶段全流程跑通，无 NaN/OOM
- Stage 3 mAP50 ≥ 0.40（预期 EMA-SimAM 相对 vanilla 提升 3-8%）
- 若 mAP50 < 0.389（vanilla 基线），需分析原因并决定是否回退

#### A3. 对比评估

在同一个 val 集上对 `weights/stage3_main.pt`（vanilla YOLO11s）和新的 EMA-SimAM Stage 3 做同口径对比：

| 对比维度 | vanilla YOLO11s | EMA-SimAM | 预期变化 |
|---|---|---|---|
| mAP50 | 0.389 | ≥0.40 | +3-8% |
| SVHBNM AP50 | 0.176 | ≥0.20 | +13% |
| VHBNL AP50 | 0.319 | ≥0.35 | +10% |
| 推理耗时 | 基线 | ≤+5% | 可接受 |

**决策点**：若 EMA-SimAM 在所有弱类（斜拉线三类 + VHBNL）上均无改善，则 revert 到 vanilla 架构，集中精力做二阶段分类器。

## 5. Phase B：二阶段状态分类器训练与验证（P0，3-5 天）

### 5.1 范围与优先级

本轮分类器聚焦于两类最容易见效的场景：

| 优先级 | 分类器 | 任务 | 预期效果 | 理由 |
|---|---|---|---|---|
| **P0** | CBHPM 二分类 | normal vs hard_spot | FP 降低 ≥30%，P 提升至 ≥0.70 | 特征最明显，快速验证管道 |
| **P0** | VHBNM/VHBNL 四分类 | normal/missing/loose/ambiguous | P 提升至 ≥0.50 | 部件状态判别是核心需求 |
| P1 | SVHBNM/SVHBNL 三分类 | normal/missing/loose | P 提升至 ≥0.30 | 需先解决数据定义问题 |
| P1 | SVHTNL 二分类 | normal/dropped | P 提升至 ≥0.30 | 需先解决结构混淆问题 |

### 5.2 数据构建

#### CBHPM 分类器数据

利用 7.14 A2 审计已产出的分类结果：
- `01_可直接保留的正确样本`：从中筛选 CBHPM 类的 TP 和 TN，作为 positive 和 strong normal
- `02_严格困难负样本候选`：90 个 HN 中筛选 CBHPM 相关的 structure_fp 样本，作为 hard negative
- `03_有效模型漏检`：68 个 FN 中筛选 CBHPM 相关的 true_fn，作为补充 positive
- 数据切分：按 source_id 隔离，禁止相邻帧跨 split

目标数据规模：

| 类别 | train | calibration | test |

## 6. Phase C：Stage 4 微调策略重新搜索（P1，1-2 天）

### 6.1 问题诊断

7.24 中 Stage 4 退化（0.389→0.379）的可能原因：

1. **freeze 0-9 过深**：新数据集的分布与 7.14 不同，freeze 过深导致无法适应
2. **零增强过于激进**：新数据集已内置 multi-scale crop 和 Copy-Paste，Stage 4 完全去掉增强可能使模型失去泛化能力
3. **lr=1e-5 过低**：在新数据规模（10,542 框 vs 2,952 框）下，低 lr 可能不足以产生有意义的参数更新
4. **val 集扩大后的噪声**：7.24 val 从 1753 扩大到 2869，更多样本意味着更大的指标波动

### 6.2 单变量实验矩阵

以 EMA-SimAM Stage 3（或 vanilla Stage 3，取决于 Phase A 结果）为起点：

| 实验 | 改动 | epoch | 预期 |
|---|---|---|---|
| S4-C | 原 Stage 4 配置重跑 | 5 | 确认退化是否可复现 |
| S4-F7 | freeze 0-7（替代 0-9） | 5 | 允许更深层适应 |
| S4-F5 | freeze 0-5 | 5 | 更大适应自由度 |
| S4-L | lr 1e-5 → 5e-5 | 5 | 加快收敛 |
| S4-A | 恢复轻量增强（translate=0.02, fliplr=0.5） | 5 | 判断零增强是否过度 |
| S4-M | 组合 freeze 0-5 + lr 5e-5 + 轻量增强 | 5 | 最佳组合猜测 |

每个实验至少跑 seed0/seed1。使用 calibration 集做筛选，禁止用 test 集反复选参。

**晋级门禁**：calibration mAP50 ≥ Stage 3 基线的 0.98 倍，且无重点类 Recall 下降 >3pp。

## 8. Phase E：完整训练、稳定性验证与最终评估（通过前置门禁后，2-3 天）

### 8.1 训练顺序

```text
Stage 1A (EMA-SimAM, mixed_pretrain, freeze backbone)
  → Stage 1B (部分解冻 backbone)
  → Stage 2 (subway_crops_1024, 域适应)
  → Stage 3 (subway_crops 1280px, 全解冻, 主训练)
  → 最优 Stage 4 配置（Phase C 选定）
  → classifier 训练（Phase B）
  → calibration 双阈值校准
  → test 一次性冻结评估
```

### 8.2 稳定性要求

- 至少 3 个仅改变 seed 的完整运行
- batch、AMP、数据、配置和代码 commit 必须一致
- 报告均值、标准差、最差 seed
- RSD≤3% 且最差 seed 仍满足研发门禁方可晋级

### 8.3 候选选择评分

延续 7.18 的业务加权评分，增加 classifier 维度：

```text
score = 0.25 × normalized(mAP50-95)
      + 0.15 × normalized(mAP50)
      + 0.20 × normalized(TP retention)
      + 0.20 × normalized(FP reduction)
      + 0.10 × normalized(per-class min P)
      + 0.10 × normalized(per-class min R)
```

否决项：任一重点类 Recall 下降 >5pp、测试泄漏、NaN、评估不完整。

## 11. 风险与应对

| 风险 | 触发信号 | 概率 | 应对 |
|---|---|---|---|
| EMA-SimAM 无增益 | mAP50 < 0.389（vanilla 基线） | 中 | 检查模块注册、初始化、训练稳定性；若确认无效则废弃，集中精力做二阶段 |
| 分类器数据不足 | 某些状态类别 <50 样本 | 高 | 优先做 CBHPM（数据充足），VHBNM/VHBNL 用数据增强补充 |
| 分类器级联后 Recall 大幅下降 | Recall 保持率 <90% | 中 | 降低 cls 阈值或改为 soft gating（`det_conf^α × cls_prob^β`） |
| Stage 4 再次退化 | 所有 S4 变体均不如 S3 | 低 | 跳过 Stage 4，S3 + classifier 即可 |
| 弱类独立源组无法短期获取 | 2 周内无新数据 | 中 | 最大化利用合成增强（Copy-Paste、Inpainting），标注质量优先于数量 |
| 训练时间不足 | RTX 4090 不可用或任务积压 | 中 | 优先保证 Phase A（EMA-SimAM）和 Phase B（CBHPM 分类器），Phase C 可降级 |
| calibration 到 test 阈值漂移 | P 或 R 下降 >10pp | 中 | 扩大 calibration 集、按场景分层、报告 CI |
