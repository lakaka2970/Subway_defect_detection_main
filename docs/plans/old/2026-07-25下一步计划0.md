## 一、位置编码注入（P0 — 最高优先级）

### 1.1 核心思想

当前模型最大的盲区是**不知道自己在看哪里**。同一个 crop 图像，来自"应有螺母的位置"和"不应有螺母的位置"，判断应完全不同。将 crop 在全图中的位置信息注入模型，让模型学习"该位置应该有什么部件"的结构先验。

### 1.2 实现方案

在数据预处理阶段，将 crop 的归一化全图坐标编码为附加通道，与 RGB 拼接后送入模型：

```python
# 数据预处理：为每个 crop 生成位置编码通道
x_norm = crop_center_x / full_image_width   # 0-1
y_norm = crop_center_y / full_image_height  # 0-1

# 方案 A：常量位置图（最简单）
pos_map = np.full((H, W, 2), [x_norm, y_norm], dtype=np.float32)
model_input = np.concatenate([crop_bgr, pos_map], axis=-1)  # H×W×5

# 方案 B：二维高斯位置编码（更丰富）
yy, xx = np.mgrid[0:H, 0:W] / H, np.mgrid[0:H, 0:W] / W
pos_map = np.stack([
    np.exp(-((xx - x_norm)**2 + (yy - y_norm)**2) / (2 * sigma**2)),  # 位置高斯
    xx, yy  # 相对坐标
], axis=-1)
```

### 1.3 模型适配

- 输入通道从 3 → 5（或更多），需修改模型第一层 Conv 的 `in_channels`
- 新增通道的权重初始化为小值（~0.01），避免破坏预训练特征
- 或者：冻结原 3 通道权重，仅训练新增通道对应的卷积核

### 1.4 预期效果

- 模型学到"位置 → 应有部件"的映射，松动/缺失类判别力质变
- 正常螺栓在不同位置有不同的"正常模式"，位置编码帮助区分
- 不需要改模型主体架构，改动最小，收益可能最大

### 1.5 实施步骤

| 步骤 | 内容 | 时间 |
|:---:|------|:---:|
| 1 | 修改裁切脚本，记录每个 crop 的全图归一化坐标 | 0.5 天 |
| 2 | 修改数据加载器，生成位置编码通道 | 1 天 |
| 3 | 修改模型 YAML 第一层 Conv 适配 5 通道输入 | 0.5 天 |
| 4 | 消融实验：有/无位置编码对比训练 | 2-3 天 |

## 二、带上下文的大窗口裁切（P0）

### 2.1 方案

当前 crop 是紧贴缺陷框裁切的 1280×1280，模型只看到缺陷局部。改为包含周围 2-3 倍上下文的大窗口：

```
当前：[缺陷框] → 1280×1280 crop（仅缺陷局部）
改进：[缺陷框 + 周围 2-3 倍上下文] → 2560×2560 → resize 到 1280
```

### 2.2 设计要点

- **上下文倍率**：以缺陷框长边为基准，裁切 2×、3× 两种窗口，随机选择
- **resize 策略**：大窗口 resize 到 1280×1280 后送入模型，保持输入尺寸不变
- **标签适配**：缺陷框坐标需按裁切窗口重新归一化
- **边界处理**：窗口超出全图边界时 padding 灰色（128,128,128）

### 2.3 预期效果

- 模型看到缺陷周围的**结构环境**（相邻螺栓、安装座、汇流排走向）
- 学到"这个位置的正常状态应该是什么样"
- 对"松动"类尤其有效：松动螺母与正常螺母的局部差异极小，但周围结构关系不同

### 2.4 与位置编码的协同

大窗口裁切提供**视觉上下文**，位置编码提供**绝对位置先验**，两者互补：
- 视觉上下文：模型看到"周围有什么"
- 位置编码：模型知道"自己在哪里"

### 2.5 实施步骤

| 步骤 | 内容 | 时间 |
|:---:|------|:---:|
| 1 | 修改 `generate_native_crops.py`，支持上下文窗口裁切 | 1 天 |
| 2 | 重新生成训练集（保留原始 crops 作为对照） | 1 天 |
| 3 | 消融实验：1280 紧密 crop vs 2560 上下文 crop | 2-3 天 |

## 三、增强策略升级（P0）

### 3.1 当前问题

Stage 3 增强偏保守（mosaic=0.05, 无 CopyPaste, 无场景增强），在数据量固定的情况下浪费了大量"免费数据"。

### 3.2 调整方案

| 增强手段 | 当前 Stage 3 | 调整为 | 理由 |
|---------|:----------:|:-----:|------|
| Mosaic | 0.05 | **0.5** | 4 图拼接，等效 4× 数据多样性 |
| CopyPaste | 0.0 | **0.5** | 将缺陷粘贴到正常背景，直接增加正样本 |
| 场景增强（隧道） | 未启用 | **0.3** | 已实现（`scene.py: tunnelize`），模拟隧道暗光 |
| 场景增强（烈日） | 未启用 | **0.3** | 已实现（`scene.py: sunlitize`），模拟高对比度 |
| 场景增强（雨雾） | 未启用 | **0.1** | 已实现（`scene.py: weather_augment`） |
| 运动模糊 | 未启用 | **0.15** | 已实现（`scene.py: motion_blur`），模拟车辆振动 |
| MixUp | 0.0 | **0.1** | 样本插值，平滑决策边界 |
| fliplr | 0.5 | 0.5（保持） | |
| flipud | 0.0 | **0.0（保持）** | 接触网有固定上下方向，禁止垂直翻转 |

### 3.3 三阶段增强递减策略（保持）

```
Stage 3（主训练）：强增强 → 学泛化
Stage 4（微调）  ：极轻增强 → 学真实分布
Stage 5（HNM）  ：关闭增强 → 学判别边界
```

### 3.4 注意事项

- CopyPaste 增强需要 `subway_defect/augmentations/defect_copy_paste.py` 中已实现的高斯模糊柔化边缘
- 场景增强函数已在 `subway_defect/augmentations/scene.py` 中实现（含夜景/IR 模拟），需在训练配置中启用
- 增强概率不宜过高，避免模型学到增强伪影而非真实缺陷特征

## 四、模型架构改进（P1）

### 4.1 CoordAtt 替换 P4 SimAM

**动机**：螺母"松动"的本质是**位置偏移**（旋转/平移）。SimAM 是零参数逐元素加权，无法建模方向信息。CoordAtt（Coordinate Attention, CVPR 2021）显式编码 x/y 方向信息，对位移敏感。

**改动**：

```yaml
# yolo11s-EMA-SimAM.yaml → 新变体
head:
  ...
  - [-1, 2, C3k2, [512, False]]    # 20 (P4/16-medium)
  - [-1, 1, CoordAtt, []]           # 21 替换 SimAM → CoordAtt
  ...
```

**参数量**：~400（极轻量），推理延迟增加 < 0.2ms

**实施**：
1. 在 `subway_defect/modules/` 中实现 `CoordAtt` 模块
2. 在 `subway_yolo/nn/Extramodule/__init__.py` 中注册
3. 创建新模型 YAML 变体
4. 消融实验：SimAM vs CoordAtt（P4 分支）

### 4.2 LSK 加入 Backbone P3

**动机**：当前 Backbone 没有任何注意力模块，特征提取完全靠标准卷积。LSK（Large Selective Kernel, ICCV 2023）能自适应选择感受野大小——对不同大小的螺栓/螺母，自动调整关注范围。

**改动**：

```yaml
backbone:
  ...
  - [-1, 2, C3k2, [512, False, 0.25]]  # 4 (P3 输出)
  - [-1, 1, LSK, [512]]                 # 4.5 新增：自适应感受野
  - [-1, 1, Conv, [512, 3, 2]]          # 5-P4/16
  ...
```

**参数量**：~2K，推理延迟增加 ~0.5ms

**实施**：
1. 实现 `LSK` 模块（大核分解 + 选择机制）
2. 注册并创建 YAML 变体
3. 消融实验：有/无 LSK

### 4.3 P2 四尺度检测头

**动机**：当前 P3（8× 下采样）最小检测目标约 160px（1280 输入）。螺母缺陷在 crop 中可能更小。P2（4× 下采样）将最小检测目标降至 ~80px。

**改动**：

```yaml
head:
  # 新增 P2 分支（从 P3 上采样 + Backbone P2 融合）
  - [16, 1, nn.Upsample, [None, 2, "nearest"]]   # P3 上采样
  - [[-1, 2], 1, Concat, [1]]                     # 与 Backbone P2 融合
  - [-1, 2, C3k2, [128, False]]                    # P2/4 特征
  - [-1, 1, SimAM, []]                             # P2 注意力（轻量）

  # Detect 改为 4 尺度
  - [[P2, P3, P4, P5], 1, Detect, [nc]]
```

**代价**：参数量 +1.5M，推理速度 -15~20%，显存 +2~3GB（预计 ~14GB，RTX 4090 可承受）

**实施**：
1. 修改模型 YAML，增加 P2 分支
2. 确保 `parse_model()` 正确解析新拓扑
3. 消融实验：3 尺度 vs 4 尺度

### 4.4 Deformable Convolution 替换 Backbone P3 标准 Conv

**动机**：螺母松动的视觉特征是**微小的几何位移/旋转**。标准卷积的固定采样网格对形变不敏感。Deformable Conv 学习每个采样点的偏移量，能自适应"跟踪"螺母位移方向。

```
标准 Conv：固定 3×3 网格采样 → 无法感知位移
Deformable Conv：学习 3×3 网格的 (Δx, Δy) 偏移 → 自适应对齐
```

**改动**：将 Backbone P3 阶段的 1-2 个标准 Conv 替换为 Deformable Conv（`DCNv2`）。

**代价**：参数量 +2K，推理速度 -10%

**实施**：
1. 在 `subway_yolo/nn/modules/` 中实现或引入 `DeformConv2d`
2. 替换 Backbone P3 的 Conv（layer 3 或 layer 4 内部）
3. 消融实验：标准 Conv vs Deformable Conv

### 4.5 架构改进实验矩阵

为避免同时改动过多导致无法归因，按以下顺序逐步实验：

| 轮次 | 改动 | 对照 | 目标验证 |
|:---:|------|------|---------|
| Exp-1 | CoordAtt 替换 P4 SimAM | 当前 baseline | 方向注意力对松动类的提升 |
| Exp-2 | + P2 四尺度检测头 | Exp-1 | 小目标 Recall 提升 |
| Exp-3 | + LSK Backbone P3 | Exp-2 | 自适应感受野的增益 |
| Exp-4 | + Deformable Conv P3 | Exp-3 | 几何形变敏感性的增益 |

每轮实验使用相同的 Stage 3→4 训练流程（可缩短为 Stage 3: 15 epochs + Stage 4: 5 epochs 做快速筛选），确认有效后再叠加下一项。

## 五、Wise-IoU 损失函数（P1）

### 5.1 动机

SPECIFICATION.md 中已规划 WIoU 但需确认是否实际启用。CIoU 在 IoU=0 时梯度为零（小框与预测框不重叠时无法学习），WIoU 通过离群度加权解决此问题。

### 5.2 改动

```python
# 当前：CIoU
box_loss = CIoU(pred_box, gt_box)

# 改为：Wise-IoU v3
box_loss = WIoU(pred_box, gt_box, outlier_threshold=0.5)
```

### 5.3 实施

1. 确认 `subway_yolo/utils/loss.py` 中是否已有 WIoU 实现
2. 若无，实现 WIoU v3（含动态非单调聚焦机制）
3. 在训练配置中切换 `box_loss` 类型
4. 消融实验：CIoU vs WIoU

## 七、多轮 HNM 迭代（P1）

### 7.1 当前问题

Stage 5 只做了一轮 HNM，误检样本挖掘不充分。

### 7.2 迭代方案

```
Round 1: Stage 4 best → 收集 FP crops → 混入训练 → Stage 5 v1
Round 2: Stage 5 v1   → 收集新 FP crops → 混入训练 → Stage 5 v2
Round 3: Stage 5 v2   → 收集新 FP crops → 混入训练 → Stage 5 v3
```

每轮挖掘出的误检样本不同（模型变强后，旧 FP 被修正，新 FP 浮现），逐步逼近真实决策边界。

### 7.3 实施

1. 将 HNM 收集 → 训练 → 评估封装为可重复执行的脚本
2. 每轮迭代后对比 P/R 变化，确认收敛后停止
3. 预计 2-3 轮迭代后 Precision 额外提升 3-5pp

### 7.4 注意事项

- 每轮新增的难负样本需人工快速抽检（50 张），确认确实是误检而非漏标
- 正负样本比例从 1:1 逐步调整至 1:1.5 或 1:2（随模型变强，需要更多负样本）
- 迭代过程中监控 Recall，若下降超过 5pp 则停止

## 十一、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 位置编码效果不显著 | P0 方案受挫 | 尝试多种编码方式（常量/高斯/可学习），做充分消融 |
| 大窗口裁切降低有效分辨率 | 小目标检测下降 | 对比 2×/3× 上下文倍率，找到最优平衡点 |
| P2 头显存超限 | 训练 OOM | 降低 batch size 或使用 gradient checkpointing |
| Deformable Conv 推理过慢 | 不满足 ≤10s | 仅在 P3 使用 1-2 层，限制变形范围 |
| 架构改动叠加后训练不稳定 | 收敛困难 | 逐步叠加（Exp-1→4），每轮确认稳定后再加下一项 |
| 分类器对"松动"类判别力不足 | 级联效果有限 | 增加分类器训练数据，或使用更大的分类器（MobileNetV3-large） |
