## 总体判断

当前瓶颈不是“再训练久一点”能解决的，而是 **训练样本尺度、检测头尺度、C2 解冻策略、C3 微调方式同时不匹配**。项目约束很明确：车载端单 RTX 4090、离线、单张 ≤10 秒，Precision/Recall 都要 ≥90%；地面端可双卡 WBF 融合，提报率还要 ≤5%。 现有推理管道本身有优势：ROI 提案后只对 60–90 个 ROI 切片做缺陷检测，总耗时估计约 5.2 秒，因此仍有空间引入 P2 小目标头、1280 输入或轻量双阶段校验。

最近 `results.csv` 反映出的核心问题也很明显：50 epoch 中 **mAP50 最好在第 6 轮约 0.3948，mAP50-95 最好在第 8 轮约 0.2876，最终反而降到 mAP50≈0.3769、mAP50-95≈0.2746**；训练 loss 持续下降，但验证 loss 和指标没有同步改善。这说明后半程主要是在记忆训练集，不是在提升泛化能力。

analysis 文件里对 C2 阶段“几乎零收益”的判断基本成立：多次运行中 C2 全模型训练只带来 +0.003～+0.018 mAP50，C3 还出现过退化；这不是小波动，而是训练流程的结构性问题。

# 一、最优先改：训练样本生成方式，而不是只改 `imgsz`

**建议把训练输入从“整张 5120 图 resize 到 1024”改成“原始分辨率 ROI/crop 切片训练”。**

现在最大的问题是：缺陷在原图里可能还有 30–60 px，但整图 resize 到 1024 后只剩几像素。analysis 中也指出，1024 输入下典型 8×8 小缺陷在 P3 只有约 1×1 特征图像素，在 P4/P5 基本不可见。

推荐训练样本构造：

| 样本类型     | 生成方式                                       | 目的             |
| -------- | ------------------------------------------ | -------------- |
| 正样本 crop | 以缺陷框为中心，从原图裁 1024/1280 patch，保留 2–4 倍结构上下文 | 保持缺陷真实像素尺寸     |
| ROI 正样本  | 使用 Stage 1 ROI 或人工结构区域裁切                   | 与推理分布一致        |
| 边界样本     | 缺陷靠近切片边缘，模拟真实切片漏检风险                        | 提升跨切片鲁棒性       |
| 难负样本     | 无缺陷但纹理相似的螺栓、绝缘子、线夹区域                       | 降低误报           |
| 全局低分辨率样本 | 少量保留整图 resize                              | 学上下文，但不作为主训练来源 |

这一步比单纯把 `imgsz: 1024 → 1280` 更关键。1280 当然有帮助，但如果仍然是整图压缩，缺陷仍会严重缩小；如果改成原生 crop，即使 1024 也能显著改善小目标可见性。

# 二、模型结构建议：车载端做 P2-Lite，地面端做异构融合

## 1. 车载端主模型：`YOLO11s-P2-EMA-SimAM-Lite`

现有车载主模型是 YOLO11s-EMA-SimAM，检测尺度为 P3/P4/P5；地面端已有 P2 四尺度模型。README 里也显示，当前 YOLO11s 是 9.5M、21.7 GFLOPs，而 P2 版本用于小目标特化。

建议新增车载端轻量 P2 版本：

```text
Backbone: YOLO11s
Neck: P2/P3/P4/P5 四尺度 FPN+PAN
Detect: [P2, P3, P4, P5]
Attention:
  P2: SimAM 或轻量 EMA
  P3: EMA
  P4: SimAM
  P5: 无注意力或仅保留上下文辅助
```

重点不是盲目加大模型，而是把容量放到小目标真正出现的尺度上。P2 对螺栓、开口销、缺失类缺陷更重要；P5 更多是结构上下文，不应承担主要分类和定位。

## 2. 注意力位置重新分配

当前 “P3 用 EMA、P4/P5 用 SimAM” 的设计有理论合理性，但对本数据不够合适。SimAM 对局部异常敏感，应优先放在 P2/P3；P4/P5 看不到足够细的缺陷，注意力反而可能强化背景结构噪声。

推荐布局：

| 层级    | 作用         | 推荐模块                  |
| ----- | ---------- | --------------------- |
| P2/4  | 微小缺陷定位主力   | SimAM 或 EMA-SimAM 二选一 |
| P3/8  | 小目标分类 + 定位 | EMA                   |
| P4/16 | 中等目标、上下文辅助 | SimAM 或轻量 ECA         |
| P5/32 | 大结构上下文     | 不加注意力或弱化检测权重          |

## 3. 加一个“局部-上下文双分支”是更有创新性的方向

可以在 head 前做一个轻量融合：

```text
Local branch: P2/P3，负责缺陷纹理、边缘、缺失区域
Context branch: P4/P5，负责判断该缺陷是否处于合理结构位置
Fusion: concat + 1×1 conv 或 gated fusion
```

这比简单堆注意力更适合接触网场景，因为很多误报来自“局部像缺陷，但结构语义不对”的区域。这个设计也容易形成项目创新点：**面向超高分辨率接触网图像的局部缺陷-结构上下文协同检测网络**。

# 三、训练流程建议：从三阶段改成五阶段闭环

现有 C1/C2/C3 思路是对的，但执行方式需要重构。README 中原始训练目标是 C1 预热、C2 全量训练、C3 微调，并希望最终达到 mAP50≥0.75、Precision/Recall≥90%。 现在的问题是 C2 没学到领域特征，C3 又容易过拟合。

推荐改为：

## Stage 0：数据与标注 sanity check

每次大训练前固定跑：

```text
1. 随机抽 50 张训练 crop 可视化标签
2. 按类别统计框尺寸、长宽比、面积分布
3. 检查 train/val 是否按源图分组，避免同源泄漏
4. 训练 20 张图过拟合测试：mAP50 应接近 1
```

如果 20 张图都过拟合不了，优先查标签、类别映射、模型 head，而不是调学习率。

## Stage 1：Head + Neck 预热，不只训练 head

冻结 backbone 前半部分，训练 neck + detect head：

```yaml
epochs: 30-50
imgsz: 1024 或 1280
freeze: backbone early layers
optimizer: AdamW
lr0: 0.001
mosaic: 0.1-0.2
copy_paste: 0
erasing: 0
```

C1 不建议强增强。目标是让检测头先适应“接触网 crop 上的小目标分布”。

## Stage 2：小目标尺度适应训练

这是新增的关键阶段，只使用原生分辨率 crop：

```yaml
epochs: 80-120
imgsz: 1280
multi_scale: 自定义 1024/1280/1536，不建议直接 ±50% 到 640
optimizer: AdamW
lr0: 0.0008-0.0012
warmup_epochs: 5-10
mosaic: 0.1-0.3
copy_paste: 0 或结构约束 copy-paste
erasing: 0
```

这里我不建议无脑启用 YOLO 默认的大范围 multi-scale，因为 1280 的 ±50% 会出现 640 输入，小目标又会被压没。更稳妥的是自定义尺度集合：`[1024, 1280, 1536]`。

## Stage 3：全模型领域自适应

这一步再全量解冻，但要用分层学习率：

```text
backbone early: 1e-5 ~ 5e-5
backbone late:  5e-5 ~ 1e-4
neck:           3e-4 ~ 5e-4
head:           8e-4 ~ 1e-3
```

如果框架暂时不支持 param group，就先用 AdamW + 较低全局 LR；不要继续用低效 SGD 小学习率硬训 200 epoch。analysis 已指出当前 C2 使用低 LR 的 SGD 时骨干特征学习效率很低。

## Stage 4：真实分布微调，不再训 50 epoch

最近结果已经说明 C3 很容易在前几轮达到最优，后续退化。因此 C3 应变成“短微调 + 早停 + EMA/SWA”：

```yaml
epochs: 20-40
patience: 8-12
imgsz: 与部署一致
mosaic: 0
copy_paste: 0
erasing: 0
lr0: 1e-5 ~ 5e-5
freeze: backbone early/middle
save_period: 1
```

并且最终模型不要默认取 last，要取：

```text
best by mAP50-95
best by recall@precision≥0.90
best by F2-score
```

因为项目硬指标是 Precision/Recall，不只是 mAP。

## Stage 5：阈值校准与部署验证

训练完成后必须做每类阈值搜索：

```text
每类单独搜索 conf_thres
目标 1：Recall ≥ 90%
目标 2：Precision ≥ 90%
目标 3：地面端提报率 ≤ 5%
```

小缺陷类别很可能需要不同阈值。统一 `conf=0.25/0.5` 不适合工业质检。

# 四、数据增强策略：从“通用 YOLO 增强”改成“结构约束增强”

当前 C2 里的 mosaic、copy-paste、erasing 对 COCO 有用，但对微小工业缺陷可能伤害更大。analysis 文件也明确指出 Mosaic、Erasing、Copy-Paste 会把小目标进一步压缩或制造不合理伪影。

推荐：

| 增强                 | 当前问题     | 建议                |
| ------------------ | -------- | ----------------- |
| Mosaic             | 小目标缩到几像素 | 降到 0.1–0.3，后期关闭   |
| Random Erasing     | 可能直接擦掉缺陷 | 关闭，或只允许擦背景        |
| Copy-Paste         | 结构位置不合理  | 改成结构约束 Copy-Paste |
| HSV/亮度             | 有实际意义    | 保留，模拟隧道、日照、曝光     |
| Blur/Noise         | 有实际意义    | 保留，模拟车载运动和压缩      |
| Perspective/Rotate | 过强会破坏结构  | 小幅保留              |
| CutMix/MixUp       | 对缺陷语义不自然 | 不建议               |

结构约束 Copy-Paste 可以这样做：

```text
1. 只在同类结构区域之间粘贴
2. 保持方向，不随意 flip
3. 贴到螺栓孔、线夹、绝缘子等语义兼容区域
4. 使用 Poisson blending 或 alpha feather
5. 粘贴后自动检查框尺寸、遮挡比例、边界完整性
```

这比普通 Copy-Paste 更有创新性，也更符合工业场景。

# 五、损失函数与样本采样：要针对“小框”和“难类”

当前指标里 Precision 明显低、Recall 也不够，说明误报和漏报都没有解决。建议从三处改：

## 1. 小目标框回归损失

小框 IoU 对 1–2 像素偏移极其敏感。可以尝试：

```text
CIoU/SIoU + NWD 辅助项
或 Wise-IoU / MPDIoU
```

更稳妥的做法是先加一个小框权重：

```text
box_loss_weight = base_weight * clamp(sqrt(mean_area / box_area), 1, 3)
```

让小目标框的定位误差在训练中不被大结构框淹没。

## 2. 分类损失加入难例权重

类别不一定极端不平衡，但“视觉难度”不平衡明显。建议：

```text
cls loss = BCE/Focal + class-balanced weight
```

权重不要只按样本数算，还要按最近验证集 AP 动态调整：

```text
AP 低的类别：采样权重提高
误报高的类别：加入更多 hard negative
```

## 3. Hard Negative Mining

每轮训练后用当前模型跑无缺陷或低置信误检区域：

```text
误检为 CBHPM/SVHBNM/VHBNL 的背景 patch
→ 加入下一轮训练负样本池
→ 不标缺陷，只作为背景学习
```

这对提升 Precision 很关键。

# 六、推理流程：保持两阶段，但加入“自适应高分辨率复检”

在 ≤10 秒约束下，不建议全图暴力提高输入尺寸。更合理的是：

```text
普通 ROI：1024 推理
疑似小缺陷 ROI：1280 或 1536 复检
低置信但结构高风险区域：二次 crop 放大复检
```

也就是：

```text
Stage 1 ROI
→ Stage 2 1024 快速检测
→ 对 0.25–0.55 置信区间的小目标候选做 1280 复检
→ WBF/NMS 融合
```

这样能把高分辨率计算集中在最需要的区域，同时保留车载端 ≤10 秒的可实现性。

地面端则继续保持异构双模型 WBF：一个三尺度模型偏 Precision，一个 P2 模型偏 Recall。README 中已有双卡异构 ensemble 设计和 WBF 阈值策略，这条路线是合理的。

# 七、推荐的落地优先级

| 优先级 | 改动                   | 原因              | 预期价值 |
| --- | -------------------- | --------------- | ---- |
| P0  | 改成原生分辨率 crop/ROI 训练  | 解决小目标被压没的根因     | 最大   |
| P0  | 新增 P2 轻量检测头          | 让模型真正看到微小缺陷     | 最大   |
| P0  | C3 改短微调 + 早停         | 最近结果已证明长训退化     | 高    |
| P1  | C2 使用 AdamW/分层 LR    | 解决骨干适应不足        | 高    |
| P1  | 降低 Mosaic，关闭 Erasing | 避免破坏小目标         | 高    |
| P1  | Hard Negative Mining | 提升 Precision    | 高    |
| P2  | 结构约束 Copy-Paste      | 增强难类，同时有创新性     | 中高   |
| P2  | NWD/Wise-IoU 小框损失    | 提升小框定位稳定性       | 中    |
| P2  | 自适应高分辨率复检            | 提高 Recall，不破坏时延 | 中高   |
| P3  | 自监督预训练/蒸馏            | 有论文价值，但工程周期更长   | 中    |

# 八、我建议的下一版实验矩阵

不要一次性全改，否则无法定位收益。建议 6 组实验：

| 实验                         | 模型      | 数据      | 训练    | 目的                 |
| -------------------------- | ------- | ------- | ----- | ------------------ |
| E0 baseline                | 当前模型    | 当前数据    | 当前流程  | 对照                 |
| E1 crop-only               | 当前模型    | 原生 crop | 当前流程  | 验证数据尺度收益           |
| E2 P2-only                 | P2-Lite | 当前数据    | 当前流程  | 验证结构收益             |
| E3 crop + P2               | P2-Lite | 原生 crop | 当前流程  | 验证主路线              |
| E4 crop + P2 + 新训练流        | P2-Lite | 原生 crop | 五阶段训练 | 目标主模型              |
| E5 E4 + hard negative + 校准 | P2-Lite | 增加难负样本  | 阈值校准  | 冲 Precision/Recall |

验收不要只看 mAP，应固定输出：

```text
mAP50 / mAP50-95
每类 Precision / Recall / F1 / F2
漏检样例 Top 50
误检样例 Top 50
按缺陷尺寸分组 AP：small / medium / large
按 ROI 类型分组 AP
单张 127MP 端到端耗时
TensorRT FP16 耗时
模型加载时间
```

## 最终推荐方案一句话

**车载端采用“原生 ROI/crop 训练 + YOLO11s-P2-EMA-SimAM-Lite + 短 C3 微调 + hard negative + 每类阈值校准”；地面端采用“三尺度精度模型 + P2 召回模型 + WBF 融合”。**

这条路线既符合单 RTX 4090、≤10 秒、离线部署的工程约束，也有足够创新性：分辨率保持训练、P2 小目标能量注意力、结构约束增强、局部-上下文协同检测、异构模型融合，都是可以写进项目报告或论文方法部分的实质性改进。
