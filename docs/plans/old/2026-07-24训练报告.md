## 4. 性能优化

### 4.1 监控工具

新建 `subway_yolo/utils/callbacks/perf_monitor.py`，通过回调系统集成到训练循环：

- **每 batch**：采样 GPU 利用率（pynvml）、记录 batch 耗时
- **每 epoch**：记录 GPU 利用率均值/峰值、VRAM、RAM、磁盘 IO、温度、功耗、train_loss、fitness
- **输出**：`perf_monitor/metrics.jsonl`（结构化日志）+ `status.json`（实时状态）

### 4.2 实验对比

| 配置 | RAM | GPU Util | 吞吐量 | 结论 |
|------|-----|----------|--------|------|
| batch=16, workers=16 (默认) | 68-71% ❌ | N/A | ~98 s/s | RAM 严重超标 |
| batch=32, workers=8 | 61% ❌ | 93.5% ✅ | ~95 s/s | RAM 仍超标 |
| **batch=32, workers=4** | **44.7%** ✅ | **93.5%** ✅ | **118 s/s** | **最优** |

### 4.3 关键发现

1. **Workers 是 RAM 主要消耗者**：16 workers 占用 ~43 GB RAM，4 workers 仅 ~28.5 GB
2. **GPU 在 4 workers 时已饱和**：增加 workers 不提升吞吐量，只增加 RAM
3. **batch=32 充分利用 VRAM**：1024px 下占用 19.5/24 GB (81%)
4. **1280px 需降 batch 至 16**：避免 OOM，VRAM 占用 16.6 GB

### 4.4 配置更新

- `subway_defect/train/configs.py`：HardwareProfile 推荐 workers=4, cache=disk
- 所有 Stage 配置：path 改为本地相对路径，batch 调整为最优值，amp=true

## 10. 遇到的问题与解决

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| RAM 超标 (68-71%) | 16 workers 占用过多内存 | 降至 4 workers |
| GPU 利用率测量不准 | epoch-end 快照捕获 GPU 空闲 | 改为每 batch 采样取均值 |
| Stage 1A epoch 3 NaN | 训练不稳定 | Trainer 内置 NaN 恢复机制自动处理 |
| 越界标签 (class_id ≥ 7) | 12 类源数据 → 7 类 crop 未过滤 | 脚本过滤 class_id ≥ 7 |
| Windows multiprocessing 崩溃 | 缺少 `if __name__ == '__main__'` 保护 | 添加 main guard |
| 输出路径错误 | YOLO 对相对路径添加 `runs/detect/` 前缀 | 改用绝对路径 |
| 无训练结果图片 | 训练脚本设置 `plots=False` | 从 results.csv 后处理生成 |
| Stage 2 val 路径错误 | 配置引用不存在的 `calibration/images` | 改为 `val/images` |

## 11. 分析与建议

### 11.1 模型性能分析

- **CBVPM/CBHPM 表现优异**（mAP50 > 0.69）：这两类缺陷视觉特征明显（断股/硬点），模型学习效果好
- **SVHBNM/SVHBNL/SVHTNL 表现较差**（mAP50 < 0.19）：斜拉线类缺陷样本少（val 仅 42-54 张），且视觉特征与背景混淆
- **VHBNM Recall 偏低**（0.423）：模型倾向于漏检吊弦断裂，可能需要更多正样本或调整置信度阈值

### 11.2 后续优化方向

1. **补充 NEU-DET + GC10-DET 数据**：增强 Stage 1A/1B 预训练的泛化能力
2. **增加斜拉线类样本**：通过数据增强或采集更多 SVHBNM/SVHBNL/SVHTNL 样本
3. **尝试 P2 小目标检测头**：斜拉线缺陷通常较小，P2 层可能提升检测率
4. **调整类别权重**：对少数类（SVHBNM/SVHBNL/SVHTNL）增加 loss 权重
5. **多尺度训练**：在 Stage 3 中启用 multi_scale 提升尺度鲁棒性

### 11.3 性能优化结论

- **最优配置**：batch=32/workers=4 (1024px) 或 batch=16/workers=4 (1280px)
- **GPU 已充分利用**：93.5% 平均利用率，接近饱和
- **RAM 控制达标**：47-50%（< 50% 目标）
- **无需进一步性能优化**：当前配置已是最优平衡点

### 13.5 数据集构建改进建议

#### 短期优化（不改数据源）

1. **降低负样本比例**：将 negatives_per_image 从 25 降至 10-15，将负样本比例从 90% 降至 ~75%。减少无效前向传播，提升训练效率
2. **类别重采样**：对少数类（VHBNL 182张, CBHPM 173张）增加 crop 数量（当前 --balance 使用 median=174，建议提高 minority 倍率至 ×3）
3. **小目标增强**：对 VHBNM/VHBNL 类启用更小的 crop 偏移（当前 ±300px），确保小缺陷不被裁切到边缘
4. **标注质量复查**：重点检查 SVHBNM/SVHTNL 类中大框（>25% 面积）的标注，确认是否存在框过大或类别标错

#### 中期优化（补充数据）

5. **补充 NEU-DET + GC10-DET**：安装 Kaggle CLI 后下载，将 mixed_pretrain 正样本从 598 提升至 ~5000+，显著增强预训练效果
6. **增加斜拉线类样本**：SVHBNM/SVHBNL/SVHTNL 三类 mAP50 均 < 0.19，需要更多高质量标注样本
7. **引入 Copy-Paste 增强**：对少数类缺陷启用 copy-paste augmentation，在不增加采集成本的情况下扩充样本

#### 长期优化（架构层面）

8. **P2 小目标检测头**：对 0.44% 面积的极小目标，标准 P3-P5 检测头感受野过大。增加 P2 层（stride=4）可显著提升小目标 Recall
9. **多尺度 Crop 策略**：当前固定 1280px crop，对小目标可尝试 640px crop + 上采样，增大目标在特征图中的占比
10. **Focal Loss 调参**：当前 fl_gamma=2.0，对极度不平衡的正负样本比（1:9）可尝试提高至 3.0-5.0

### 14.2 train_pipeline.py 一键训练 vs 本次实际训练

`train_pipeline.py` 支持一条命令启动全部训练：

**本次训练与 pipeline 的关键差异：**

| 项目 | 本次实际训练 | train_pipeline.py |
