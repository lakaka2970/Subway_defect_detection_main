## 2. 训练管道架构

本次采用了4阶段渐进式训练策略，每阶段继承前一阶段的最佳权重：

```
Stage 2 (领域自适应)         Stage 3 (主训练)         Stage 4 (短微调)         Stage 5 (难负样本)
┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
│ • 冻结backbone    │       │ • 全解冻训练       │       │ • 冻结backbone    │       │ • 冻结backbone    │
│ • 1024px分辨率    │  ───▶ │ • 1280px高分辨率   │  ───▶ │ • 极低LR=5e-5     │  ───▶ │ • 超低LR=1e-6     │
│ • 适度数据增强     │       │ • WIoU损失        │       │ • 极小数据增强     │       │ • 零数据增强       │
│ • CIoU损失        │       │ • 强数据增强       │       │ • 真实分布精调     │       │ • 难负样本训练     │
│ • 20 epochs      │       │ • 45 epochs      │       │ • 15 epochs      │       │ • 10 epochs      │
│ init: Stage1B    │       │ init: Stage2     │       │ init: Stage3     │       │ init: Stage4     │
└─────────────────┘       └─────────────────┘       └─────────────────┘       └─────────────────┘
```

### 4.3 分析

- **关键转折点**: 第 11 epoch 出现训练损失大幅下降（box_loss: 1.941 → 1.601），可能是 copy-paste 增强的正样本多样性和 WIoU 损失共同作用的结果。
- **Close Mosaic 效应**: 第 35 epoch 关闭 Mosaic 后，mAP50 从 0.466 提升至 0.476（+2.1%），表明模型在接近真实分布的训练后期受益于原生分辨率微调。
- **最佳 epoch**: 第 43 epoch 达到峰值 mAP50=0.476, mAP50-95=0.362。早停未触发（耐心值=15），全部 45 epoch 执行完毕。
- **vs Stage 2 提升**: mAP50 +18.4% (0.402 → 0.476), mAP50-95 +38.7% (0.261 → 0.362)。全解冻 + 高分辨率 + WIoU 组合带来了显著的性能跃升。
- **收敛状态**: 最后 10 个 epoch mAP50 在 0.466–0.476 之间波动，验证损失基本持平，模型接近收敛但仍有小幅波动。
- **Precision-Recall**: Precision 从 0.291 提升至 0.404，Recall 从 0.527 提升至 0.574，两者同步提升说明 WIoU 有效平衡了定位和分类。

### 5.3 分析

- **持续提升**: 15 个 epoch 全部执行完毕，早停未触发，mAP50 从 0.468 稳步提升至 0.520（+11.1%）。
- **低 LR 策略验证**: 5e-5 恒定学习率 + 无 warmup 的设计有效避免了之前训练中 bias LR 异常飙升的问题（v2 关键修复）。
- **最小增强策略成功**: 关闭所有几何增强（Mosaic/MixUp/Copy-Paste）、仅保留极轻的 HSV 抖动（h=0.003, s=0.1, v=0.1），使模型直接拟合真实推理分布。
- **vs Stage 3**: mAP50 +9.2% (0.476 → 0.520), mAP50-95 +12.6% (0.362 → 0.407)。
- **Precision 提升**: 从 0.404 → 0.469（+16.1%），说明低 LR 微调有效减少了虚警，同时 recall 保持在 0.582 的较好水平。
- **最佳模型选择**: **Epoch 15 (last.pt)** 即为最佳，验证损失和 mAP 在最终 epoch 持续改善。

| 3 | 0.297 | 0.125 | 0.494 | 0.383 | 0.484 | 0.542 | — |

### 6.3 分析

- **Precision-Recall 权衡**: 这是硬负样本挖掘的预期行为 — Precision 从 0.469 → 0.534（+13.9%），但 Recall 从 0.582 → 0.503（-13.6%）。
- **mAP 轻微下降**: mAP50 从 0.520 → 0.506（-2.7%），这在意料之中，因为硬负样本挖掘的目标是**减少误检**而非单纯提升 mAP。
- **训练稳定性**: 训练损失从 0.315 平滑降至 0.288，验证损失几乎持平，模型在极小学习率下稳定微调。
- **cls_loss 下降显著**: 分类损失从 0.140 → 0.103（-26.4%），说明难负样本有效帮助模型学习"什么不是缺陷"。
- **部署考虑**: Stage 5 模型适用于对 Precision 要求更高的场景（减少人工复核工作量），但若更关注检出率（Recall），Stage 4 模型更为合适。推荐根据实际业务需求选择部署哪个阶段的权重。

### 8.5 7/27 → 7/28 提升分解（同模型、同数据、同管道）

本次运行（7/28）相较上一次（7/27）实现了显著提升，尽管使用**完全相同的模型架构、数据集和训练管道**。提升来源于以下配置改进：

| 改进项 | 7/27 | 7/28 | 影响 |
|--------|:----:|:----:|------|
| **cache** | disk（仅 S2/S4） | **全阶段 disk** | 跳过重复 JPEG 解码，训练加速 ~30% |
| **workers** | 0（全阶段） | **S3=2, 其余=0** | Stage 3 数据加载提速 |
| **persistent_workers** | false | **S3=true** | 减少 worker 重启开销 |
| **amp** | S5 全程 true | S5=true（一致） | — |
| **训练稳定性** | 多次中断重启 | **一次性完整运行** | 避免权重链污染 |
| **Stage 5 batch** | 8 | **12** | 更大 batch，训练更稳定 |

**关键改进归因：**

1. **全阶段一次性完整运行**（最重要）：7/27 因 DataLoader 死锁、VRAM 溢出、手动终止等原因经历了 5 次中断重启。每次中断后 checkpoint 恢复可能未完全对齐优化器状态，权重链存在"污染"风险。7/28 一次性无缝完成全部 4 个阶段。

2. **cache=disk 全阶段覆盖**：7/27 中仅 Stage 2 和 Stage 4 使用了 cache=disk。7/28 所有 4 个阶段均启用，大幅减少数据加载延迟，使训练循环更稳定。

3. **Stage 3 workers=2 + persistent_workers**：7/27 中 workers=0（安全但慢），导致 Stage 3 每 epoch 耗时 17.8 分钟。7/28 在 spawn 上下文保护下安全启用 workers=2，每 epoch 降至 9.3 分钟。更快的数据加载减少了 GPU 空闲等待时间，同时使 batch 间的噪声更均匀，有利于优化器收敛。

## 9. 关键发现与分析

### 8.1 成功经验

1. **渐进式训练管道设计有效**: 4阶段管道从粗到精，逐步提升模型能力。Stage 3（全解冻主训练）贡献了最大的性能增益（+18.4% mAP50），Stage 4（低LR微调）进一步提升了真实分布上的表现（+9.2% mAP50）。

2. **WIoU 在主训练阶段表现优异**: Stage 3 使用 WIoU 代替 CIoU，mAP50-95 提升了 38.7%。WIoU 的动态权重机制对接触网缺陷这种尺度差异大的目标检测任务特别有效。

3. **v2 学习率修复验证成功**: Stage 4 采用 `warmup_epochs=0` + `lrf=1.0` + `cos_lr=false` 的设计，有效避免了之前训练中 bias LR 异常飙升（曾达 0.067）的问题。本次训练从头到尾学习率保持稳定，Precision 持续改善。

4. **Close Mosaic 策略有效**: Stage 3 在第 35 epoch 关闭 Mosaic 增强后，mAP50 额外提升了 2.1%，验证了"Mosaic 训练 + 原生分辨率精调"两阶段策略的正确性。

5. **硬负样本挖掘达成 Precision 目标**: Stage 5 将 Precision 提升至 0.534（+13.9%），有效减少了误检，适合部署在需要降低人工复核量的场景。

### 8.2 待改进领域

1. **Recall 瓶颈**: 最终 Stage 4 的 Recall 在 0.582，说明还有约 42% 的真实缺陷未被检出。需要通过以下方式改进：
   - 增加难例正样本（小目标、遮挡、模糊场景）
   - 尝试 Focal Loss 的 gamma 参数调优
   - 考虑使用更大的模型变体（yolo11m-v2）

2. **12类不均衡问题**: 需要查看每类 AP 来确认是否存在长尾分布问题。建议对低 AP 类别（如 INSD、DRPS）进行针对性数据扩充。

3. **Stage 5 的 recall 损失**: 硬负样本训练导致 recall 下降 13.6%。建议尝试：
   - 调整正负样本比例（当前 1:1，可尝试 2:1 或 3:1）
   - 降低 Stage 5 分类损失权重
   - 使用 per-class confidence threshold 校准来在推理阶段恢复 recall

4. **mAP50-95 仍有提升空间**: 最终 0.407 的 mAP50-95 说明模型在高 IoU 阈值下的定位精度有改进空间。可考虑增加 DFL 损失权重或使用更长的 Stage 3 训练。
