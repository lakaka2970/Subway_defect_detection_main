日期：2026-08-29

DG-v1 权重：`DG-v1_20260828/best.pt`（SHA256 `42e59646…`）

## 0. 一句话结论

**DG-v1 的执行是严谨的，但它解决的问题是错的。**

本项目当前的主要矛盾不是"域泛化能力不足"，而是**训练数据集在 8 月重构时被整体换成了车间单日拍摄数据，导致唯一与部署域同源的检测车实拍数据被移出训练集、只留作测试集**。DG-v1 试图用无监督风格扰动去弥合一个由数据选型造成的鸿沟，这在原理上够不着；它的失败是设计前提的失败，不是调参的失败。

DG-v1 应作为**高质量的失败基线**保留（其域差异量化表、错误分类学、Material Passport 都可直接复用），但**不应继续沿 DG 路线迭代**。下一步必须回到数据层：重建"混合域训练集 + 跨线路评估基准"，把 770 张真实线路数据的监督信号用起来。

# 第一部分　对 DG-v1 的评价

## 1.1 值得肯定的部分

这轮工作里有几件事做得比项目此前任何一轮都扎实，应当保留为项目规范：

1. **数据纪律明确且被遵守。** 770 张外部图不进梯度、不参与 checkpoint 选择，纯测试前后 `best.pt` 的 SHA-256 一致，有哈希为证。这是本项目第一次做到可证明的测试隔离。
2. **先量化后动手。** 域差异报告给出了亮度 135.1→45.2、饱和度 22.8→0、目标/邻域亮度差 33.7→3.5 等 12 项可复核的中位数指标，而不是靠肉眼下结论。
3. **错误分类学做得对。** 把 2057 个误报拆成"纯背景误报 99.32% / 错分类 0.14%"，把 814 个漏报拆成"GT 附近无任何预测 98.40%"，直接排除了"框回归精度不足"和"分类器边界不清"这两个常见的错误方向。
4. **结论不粉饰。** 明知是自己的方案，仍明确写"不通过、不建议部署"，并指出 FP 恶化 37.13%。这避免了本项目此前多次出现的"用同域 mAP 自我确认"的陷阱。
5. **Material Passport 完整。** commit、脚本哈希、种子、驱动版本齐全，可复现。

## 1.2 设计层面的七个问题（按严重度排序）

### 问题 1（致命）：诊断对了现象，判错了病根

报告把问题定义为"训练中心彩色明亮域 vs 实际线路灰度低照度域的域偏移"，并据此选择 DG 技术路线。但数据血缘显示，这个域偏移不是客观条件限制，而是**8 月数据重构时的一次选型结果**：

| 事实 | 出处 |
|---|---|
| `train_data_2` 的 1039 个拍摄组**全部**来自 2026-07-28，时段 09:00–10:59 | `data/train_data_2/manifest.json` → `group_assignments` |
| 3789 张源图全部为 `IMG_20260728_*` 命名（车间静态拍摄） | `data/Defect_dataset_2/Defect_dataset/images/` |
| 项目**原本拥有**检测车实拍数据 `data/Defect_dataset`：899 张 / 2482 个实例 / 7 类 | `docs/Defect_dataset_2统计报告.md` |
| 这 899 张中的 **500 张**就出现在 770 张"外部测试集"里 | 文件名比对（本地 502 张，重叠 500 张） |
| 770 张 = 旧 `Defect_dataset` 的 16 类重标注版（899 张/2482 框 → 770 张/814 框） | 命名规则一致（`102903294_K26305_F1B03-146_1_21.jpg`） |

也就是说：**项目手里一直有部署域的标注数据，却在扩到 16 类时把它整体剔除了，然后反过来把"模型不认识部署域"当成需要算法攻克的科研问题。**

DG 路线的隐含前提是"目标域无标注"。本项目不满足这个前提。

### 问题 2（严重）：特征域探针的样本量使 AUC=1.000 成为统计必然，不构成证据

`probe_manifest.json` 实测：**探针每域只有 12 个样本，共 24 个**。而探针特征是各层激活（层 2 有 256 通道，深层 512–1024 通道）。

在 24 个样本、数百到数千维特征上训练一个线性分类器，两类**任意**随机样本集都几乎必然线性可分，AUC=1.000 是过拟合的必然结果，不是"模型没有学到域不变表示"的证据。报告中也未提及探针做了训练/测试切分。

两个直接后果：

- **"域探针 AUC 仍为 1.000 → 域不变性失败"这条推理链不成立。** 它不能作为 DG-v1 失败的证据，也不能作为后续实验的判据。
- **方案 §6.5 与报告 §10.6 提出的"域探针 AUC 降到 0.8 以下"是一个不可达且无意义的门槛。** 若沿用，后续任何实验都会在一条假指标上被误判。

探针的另两项（`train/actual_activation_enrichment`、`counterfactual_cosine`）虽同样只有 24 样本，但**激活富集比 2.30 vs 1.25 的差距方向明确、与外测结果一致**，属于有价值的弱证据；`counterfactual_cosine` 全部在 0.93–0.99 区间，已饱和，无区分力，建议弃用。

### 问题 3（严重）：MixStyle 的位置与剂量不足以影响决策层

| 项 | DG-v1 取值 | 问题 |
|---|---|---|
| 插入层 | 2、5 | 仅覆盖 backbone 浅层。检测头层 22/26/30/34 完全不受影响，而这些层才是产生 2840 个误报的地方 |
| `p` / `alpha` | 0.5 / 0.1 | alpha=0.1 属于极弱混合；MixStyle 原文常用 alpha=0.1 但配合多域批采样，本项目实际只有一个源域 |
| batch | 8 | 批内统计估计噪声大，8 样本的通道均值/方差交换本身就不稳定 |
| 与 aux_head 冲突 | 层 5 同时是 `aux_head.layer: 5`（9 类部件分类，loss_weight 0.1）的输入 | 部件分类头在训练时看到的是风格被扰动的特征，而验证/推理时看到的是干净特征，形成训练-推理不一致 |

方案 §7 已经预写了应对分支（"若层 2/5 域 AUC 降低、深层仍高，则下一轮加入更深层 MixStyle/IBN"）。实测正是这个分支，但报告结论没有据此收敛，反而列出了 9 条并列的下一步建议，没有优先级。

### 问题 4（中等）：剔除离线增强图，反而砍掉了唯一的低照度样本来源

DG-v1 把 5211 张离线增强图全部排除，只留 2570 张基础原图。动机（避免重复背景被反复记忆）是对的，但有一个未被评估的副作用：

`train_data_2` 的 12 种离线变体里包含 `night`、`tunnel`、`degrade`、`bgblur`、`defocus` —— 这是训练集中**唯一**把亮度往 45 附近推的样本。剔除它们之后，DG-v1 的在线增强只做了 gamma 0.55–1.45、brightness 0.45–1.1、gray_p 0.6。

外部 FP 从 2071 涨到 2840（+37.13%）与这一点是自洽的：**模型的低照度/低对比样本暴露量下降，对暗场景的判别边界变得更自信但更错。** 这一项需要在下一轮做显式消融（见 3.5 A/B 组）。

### 问题 5（中等）：方形随机裁剪改的是构图，改不了传感器响应与上下文

`square_crop_p=0.5`、尺度 0.55–0.95 确实把 4:3 变成了 1:1。但两域的根本差异是：

- **传感器响应**：亮度 135→45、饱和度 23→0、熵 3.46→1.69。裁剪不改变成像响应。
- **语义上下文**：车间整图 letterbox 后，网络看到的是"完整工件 + 安装底座 + 车间墙面"；检测车 1280 滑窗后，网络看到的是"一段隧道里的局部结构"。这是**视野语义**的差异，随机裁剪一个特写图并不能凭空造出隧道上下文。
- **有效分辨率**：车间 8192×6144 letterbox 到 1280 是 6.4× 降采样；检测车 5120×5120 切 1280 tile 是 4× 降采样。目标进入网络的短边 99 px vs 193.5 px，差约 2 倍。随机裁剪改变的是选取区域，不解决这个标定问题。

### 问题 6（中等）：零样本类别权重 0.001 是安慰剂

`class_weights[7..10] = 0.001`。对梯度而言，一个没有正样本的类别，**任何权重都产生不了监督信号**；而 0.001 的负权重（把其他类判为非该类）还会反向挤压。这不是错误，但应在报告中明确标注为"无操作项"，避免被误读为已采取措施。

真正的关键在于：**外部测试里 RHTBNM 67 + RHTBNL 51 = 118 个目标，占全部 814 个 GT 的 14.5%。而这 118 个目标的标注，就躺在 770 张图里没人用。**

### 问题 7（轻微）：单轮改 6 个变量，无法归因

DG-v1 同时改动了：①全量解冻 ②MixStyle ③传感器在线增强 ④方形裁剪 ⑤数据量砍到 1/3 ⑥类别权重。外测结果变差时，无法定位是哪一项的功劳或责任。

**这正是 8 月 13 日 `train_data_3` 那轮已经踩过的坑**（同时改数据源 + 三组新增强 + 类别权重 → CBHPM 召回崩到 0.347 → 无法归因 → 整体回退）。8.14 报告里已经写了"用消融实验替代一次改全部"，DG-v1 没有吸收这个教训。

## 1.3 被误读的历史教训：8 月 13 日那轮不该被全盘否定

`docs/plans/2026-08-14_train_data3_训练报告.md` 记录了项目唯一一次"把检测车数据加回训练集"的尝试：

- 从 `Defect_dataset` 补充 CBHPM +296 张、CBVPM +230 张源图；
- 结论：内部 val mAP50 0.961 → 0.901，**判定为失败并整体回退**。

这个判定有两个问题：

1. **判定指标选错了。** 内部 val 619 张中绝大多数仍是车间数据。一个"让模型更适应检测车域"的改动，用"车间域 val mAP"来判死刑，等于用错误的尺子量正确的方向。
2. **从未在 770 张真实线路集上评估过。** 那轮权重如果拿到外部集上测，很可能是本项目第一个 TP > 1 的模型。权重没下载，这个假设已无法验证——但它说明：**项目已经两次把可能有效的方向，用无效的指标否掉了。**

另外，8.14 报告把失败归因于"标注口径不一致"——这个判断很可能是对的，但归因不完整。因为 `Defect_dataset`（2482 框 / 7 类）与 `Defect_dataset_16`（814 框 / 16 类）之间，**不只是口径差异，而是标注标准发生了根本变化**：VHB\*/SVHB\* 系列在新标注中大量被删除或重判。所以正确的结论不是"不能合并老数据"，而是：

> **不要用旧的 7 类 `Defect_dataset` 标签；要用重新标注后的 16 类 `Defect_dataset_16`。**

这一点直接决定了 DG-v2 的数据配方（见 3.2）。

## 1.4 结果解读：这是评估体系的失灵，不只是模型的失灵

| 数据集 | 指标 | 数值 |
|---|---:|---|
| 车间内部测试 551 张 | mAP50 | 96.17% |
| 检测车外部 770 张 | Recall（16 类口径） | 0.1229% |

96% 与 0.1% 同时存在于同一个权重上。这说明 **mAP50(车间 val) 与部署可用性之间的相关性约等于零**。项目过去三个月几乎所有"是否下载权重""是否采纳改动"的决策，都以这个指标为准（`train_pipeline.py` 的 `best.pt` 选择、8.14 的回退决策、Stage 5 的弃用决策）。

因此 DG-v2 的第一优先级不是改模型，是**换掉这把尺子**。

# 第二部分　根因重判

## 2.1 因果链

```
8 月数据集重构
  → 采用 Defect_dataset_2（车间，2026-07-28 单日上午，1039 个拍摄组，4:3 彩色高亮）
  → 检测车实拍的 Defect_dataset（899 张）因只有 7 类、与 16 类体系不符而被整体移出训练
  → train_data_2 成为唯一训练集（2570 基础图 + 5211 同背景离线增强）
  → 同域 val/test 与训练图共享采集地点、设备、背景、光照 → mAP50 96% 但只证明同分布拟合
  → 部署域（检测车 5120×5120 灰度低照度滑窗）与训练域在像素层几乎无交集
  → 模型的"缺陷证据"建立在颜色、高对比边缘、车间材质、完整工件构图上
  → 在真实线路上：真实缺陷对比度只有 3.5 → 看不见；规则设施边缘被当成缺陷 → 到处报
  → TP=1 / FP=2840 / FN=813
```

## 2.2 为什么 DG 路线在原理上够不着

DG 方法（MixStyle、IBN、域对抗）的目标是：在**无法获得目标域标注**时，通过让特征对"风格"不敏感，换取跨风格迁移。它有两个硬约束：

1. **它只能对齐风格，不能对齐内容。** 车间图和隧道图的内容差异（工件特写 vs 隧道局部、有无支架墙面、目标相对尺寸 2 倍差）不是风格，是语义。让模型对这些不变，等于让它对任务不变。
2. **它需要目标域样本参与对齐。** DG-v1 明确禁止 770 张参与训练，于是 MixStyle 只能在**同一个源域内部**做批统计交换——它没有第二个域可以混合。这是 DG-v1 最根本的结构性缺陷：**用单域数据做跨域正则化，MixStyle 退化成一种普通的噪声增强。**

而本项目恰恰**有**目标域标注（770 张 / 814 框 / 6 类，含 118 个 RHT 目标）。放着监督信号不用去求无监督不变性，是路线错配。

## 2.3 可以同时排除的几个假设

| 假设 | 判定 | 依据 |
|---|---|---|
| 小目标分辨率不足 | 排除 | 实际目标网络内短边 193.5 px > 训练 99 px |
| 置信度阈值设置不当 | 排除 | 唯一 TP 与大量 FP 都压在 0.25 附近，调阈值必然同向删增 |
| 框回归精度不足 | 排除 | 99.32% 误报与任何 GT 的 IoU < 0.1 |
| 类别分类边界不清 | 排除 | IoU≥0.5 的错分类仅 3 例 |
| P2 检测头导致误报 | 未定 | 误报框短边中位 163 px，非细碎纹理；须受控消融，不可直接删 |
| 类别不均衡 | 次要 | 类别权重救不了坏数据（8.14 已验证） |

# 第三部分　DG-v2 行动计划

## 3.0 总原则

> **先换优化目标，再换算法。在数据层没做完之前，不再做任何架构级消融。**

三条硬规则，写进项目规范：

1. **任何"是否采纳"的决策，一律以跨线路验证指标为准；车间内部 val mAP 只用于监控训练是否正常收敛，不用于选权重、不用于判定成败。**
2. **每轮只改一个变量。** 沿用 8.14 报告提过的 A/B/C 消融法，探针跑 15–20 epoch 定方向，全量只跑确认过的配方。
3. **所有最终结论必须在从未参与任何方案设计的新线路数据上复核。** 770 张已经参与了 DG-v1 的诊断，它只能当开发集，不能当验收集。

## 3.1 P0-A：重建评估基准（第 1 周，不依赖 GPU）

这是整个计划里投入产出比最高、也最容易被跳过的一步。

### 3.1.1 用文件名里的线路段做分组切分

770 张中 721 张为标准检测车命名 `{序号}_K{公里标}_{线路段}-{支柱号}_{n}_{m}.jpg`，可提取出天然的物理分组：

| 线路段 | 图像数 | 建议用途 |
|---|---:|---|
| F1B04 | 326 | CV 折 1 |
| F1B03 | 186 | CV 折 2 |
| F1A01 | 88 | CV 折 3（与 F1A02 合并 = 96） |
| F1B05 | 53 | CV 折 4（与 F1B01+F1B02 合并 = 113） |
| F1B01 | 48 | CV 折 4 |
| F1B02 | 12 | CV 折 4 |
| F1A02 | 8 | CV 折 3 |
| 非标准命名（`1.jpg`…`49.jpg` 等 49 张） | 49 | 来源不明，**只进训练池，永不进测试** |

### 3.1.2 采用"留一区段交叉验证"（LOSO-CV）

只有 814 个 GT，切成固定 train/val/test 会让每一份都小到不可用。改用 4 折留一区段：

- 每次留出 1 个线路段作测试，其余 3 段 + 车间数据作训练；
- 4 折轮换，最终报告 **4 折宏平均**；
- 由于测试段在训练中完全未出现（不同线路、不同公里标区间），这等价于 4 次独立的跨线路迁移测试；
- 每折内部再从训练段里划 15% 做早停监控（同样按线路段/公里标分组，不做随机切分）。

**好处**：814 个 GT 全部被评测到，且每一次评测都是跨域的；不需要牺牲数据量换测试集。

### 3.1.3 冻结评估脚本与指标口径

新建 `scripts/eval_loso_cv.py`，一次性写死并版本化：

- 推理协议：1280×1280 tile，stride 960，NMS IoU 0.5，匹配 IoU 0.5，max_det 300；
- 主指标：**每类 AP50 + 宏平均 AP50**、**16 类口径 TP/FP/FN**、**每图平均 FP**、**无缺陷图误报率**（770 张中有 199 张 GT=0，这是现成的低误报测试床）；
- 次指标：mAP50-95、每类 P/R；
- **禁止**在最终报告里混用"仅 GT 类"与"全 16 类"两种口径（DG-v1 报告已因此产生阅读歧义，两类口径必须分表列出）；
- 输出带 95% 置信区间（bootstrap 1000 次）。814 个 GT 下任何单点差异若无置信区间支撑，都不可信。

### 3.1.4 建立真盲测集（本月内启动采集）

770 张已参与诊断，不能作为验收依据。需从**未参与任何分析的线路/区段**（例如 F1B06 或其他线路）新采集 300–500 张，标注后封存，只在 10 月最终评估时解封一次。这是 10.15 交付前唯一的合规验收依据。

## 3.2 P0-B：混合域训练集 + 原生滑窗协议（第 2–3 周）

这是 DG-v2 的主体实验。

### 3.2.1 协议对齐：把车间图按检测车的方式切

当前最大的协议错配是：**训练时看整图 letterbox（完整工件特写），推理时看 1280 滑窗（隧道局部）**，且有效分辨率差 1.6 倍。

标定方法（先抽 200 张标定，再全量生成）：

1. 统计车间图目标在原图上的短边中位数：`99 px × 6.4 ≈ 634 px`；
2. 目标网络内尺度对齐到实际域的 `193.5 px` → 缩放因子 `s ≈ 634 / 193.5 ≈ 3.3`；
3. 车间图先整体下采样 `s` 倍（8192×6144 → 约 2480×1860），再按 **1280 tile / stride 640** 滑窗切图，同步换算 YOLO 框；
4. 每图约 6 个 tile，2570 张基础图 → 约 15,400 个训练 tile；
5. **保留 20% 车间整图 letterbox 样本**作为对照组（防止完全丢失全局上下文，也为消融提供变量）。

> 注：这一步是纯粹的几何/协议工程，不需要新标注，成本主要是脚本与一次数据生成（约 1–2 小时）。它是本计划中**最可能带来数量级改善**的单点改动，因为它直接消除了"训练看到完整工件、推理看到隧道局部"的语义错配。

### 3.2.2 混合配方

| 源 | 内容 | 处理 | 预估量 |
|---|---|---|---:|
| A 车间 | `train_data_2` 2570 基础图 | 按 3.2.1 切片；在线 mild 增强 | ~15,400 tile |
| B 真实线路（当前折的训练段） | 770 张中的 ~540–720 张 / ~600 GT | 原生 1280 tile / stride 960；**不做**几何形变与阴影类增强 | ~2,500 tile |
| C 车间离线增强（受控） | `night` / `tunnel` / `degrade` 三种低照度变体 | 同 A 切片 | 消融开关 |
| D 无缺陷真实线路背景 | 770 张中 GT=0 的 199 张（取当前折的训练部分） | 空标签，作为硬负样本 | ~150 张 |
| E 挖掘硬负样本 | 在训练折上跑当前模型，取 conf>0.25 的纯背景误报框 | 空标签 + 原图 | 迭代添加 |

混合比例建议起点 **A:B = 3:1**（按 tile 数），做 1:1 与 5:1 两档消融。

### 3.2.3 训练配置

沿用已验证的部分，只改必要项：

| 项 | 值 | 说明 |
|---|---|---|
| 初始化 | `stage4_best.pt` | 保留 16 类检测能力；若 B 源表现不稳，对照组从 COCO 重训 |
| epochs / 早停 | 40 / patience 20 | 8.14 已证明 patience 过小会截断收敛 |
| imgsz | 1280 | 与推理一致 |
| batch | 16（tile 化后显存更可控） | DG-v1 用 8，MixStyle 需要大批；本轮若不用 MixStyle 可提至 16 |
| 优化器 / lr0 | AdamW / 1e-4（新数据需更大步长） | DG-v1 的 5e-5 是精调量级 |
| 冻结 | 全解冻 | 需要浅层适应传感器响应 |
| 损失 | WIoU + Focal（沿用） | |
| 增强 | 保留 gray / gamma / 噪声 / 轻模糊；**对 CBHPM、CBVPM、VHBNL、SVHBNL 禁用 elastic 与 defect_shadow** | 8.14 已证明这两类增强对细微特征有破坏性 |
| 类别权重 | 按混合后真实频率的平方根倒数重算；**对仍为 0 样本的 GWCSBNM/GWCSBNL 明确标注为"不可识别"，权重设 0 而非 0.001** | |

### 3.2.4 判据（DG-v2a）

| 门槛 | 目标 | 说明 |
|---|---|---|
| LOSO-CV 宏平均 Recall（4 个有监督外部类 CBHPM/CBVPM/INSD/DRPS） | **≥ 40%** | 从 0.12% 起步，40% 是"模型开始工作"的信号 |
| 每图平均 FP | **≤ 2.0** | 当前 2840/770 = 3.69 |
| 无缺陷图（GT=0）误报率 | **≤ 30%** | 当前 > 95% |
| 车间内部 val mAP50 | ≥ 0.93 | 允许下降 0.03，作为过拟合护栏 |

**达不到 40% Recall 就停在数据层继续找原因，不进入算法消融。**

## 3.3 P0-C：硬负样本闭环（第 3 周，与 3.2 并行）

199 张 GT=0 的真实线路图是现成的低误报测试床，且当前模型在其中 96% 上都报出了缺陷。做法：

1. 用 DG-v1 在训练折上推理，导出所有 conf ≥ 0.25 且与任何 GT 的 IoU < 0.1 的框；
2. 按类别聚类（预期集中在 GWCNL 614、BSBM 459、INSD 742、VHBNL 158）；
3. 把这些框所在的 tile 以**空标签**加入训练集，权重高于普通背景；
4. 每轮迭代重复一次，观察每图 FP 是否单调下降。

这一步直接针对"规则设施背景被当作缺陷"这一条已确认的误报主因。

| 类别 | 现状 | 动作 | 责任方 |

## 3.5 P2：算法侧消融（明确降级，仅在 3.2 达标后启动）

按优先级排队，每轮一个变量，均用 3.1 的 LOSO-CV 评估：

| 编号 | 变量 | 设置 | 触发条件 |
|---|---|---|---|
| A | 车间离线低照度变体 | 开 / 关 | 用于验证问题 4（剔除增强是否帮了倒忙） |
| B | 原生滑窗切片 | 100% 切片 / 80% 切片 + 20% 整图 letterbox | 验证协议对齐的贡献 |
| C | P2 检测头 | 四头 / 三头（P3–P5）/ P2 门控 | 数据层达标后，在相同数据与 seed 下受控比较每图 FP |
| D | MixStyle 位置与强度 | 关 / 层 2+5 / 层 2+5+22+26+30+34，alpha 0.1 vs 0.3 | 有了 B 源后 MixStyle 才有第二个域可混合，此时才可能生效 |
| E | IBN / 域对抗头 | 关 / 开 | D 有效才做 |
| F | 监督对比学习（同类别跨成像域拉近） | 关 / 开 | D、E 有效才做 |

**D–F 是论文向工作，不是交付路径。** 在时间压力下，C 之后的预算应让位于数据增量。

## 3.6 立即停止 / 立即修正的六件事

1. **停止用车间内部 val mAP50 选 `best.pt`。** 改选"车间 val + 当前折真实线路 val 的混合 fitness"。
2. **停用"域探针 AUC"作为判据**（样本量 24，指标无效）。若要保留，必须把每域样本提到 ≥ 200 并做 train/test 切分，且仅在**同内容配对**（同类、同构件、同尺度）的样本上比较才有意义。
3. **停用 `counterfactual_cosine`**（已饱和在 0.93–0.99，无区分力）。
4. **修正类别编号文档冲突。** `改进计划` 表 2-1 写 `5=RHTBNM, 6=RHTBNL, 7=GWCSBNM…13=CBHPM, 14=CBVPM, 15=DRPS`；而模型与数据实际为 `5=CBHPM, 6=CBVPM, 7=RHTBNM, 8=RHTBNL, 9=GWCSBNM, 10=GWCSBNL, 11=GWCNM, 12=GWCNL, 13=BSBM, 14=INSD, 15=DRPS`（见 `data/train_data_2/classes.txt` 与外部测试 `per_class_metrics.csv`）。**两份口径完全不同**，而前者是要交付给甲方的文档。同时 `subway_defect/models/yolo11s-v2.yaml` 仍写 `nc: 18`。这是交付级风险，本周内必须统一。
5. **把 DG-v1 的两个脚本补进仓库。** `scripts/train_domain_generalization.py` 与 `scripts/pure_test_sliding_770.py` 目前只存在于远端 `/root/autodl-tmp/inspection-develop`，仓库内 `git log` 最后提交停在 8-16。没有脚本，Material Passport 里的哈希无法复现。
6. **不要再往 770 张上做更多诊断性推理。** 它已被用于方案设计，继续观察只会让自适应偏差累积。所有新观察一律走 3.1.4 的真盲测集。
