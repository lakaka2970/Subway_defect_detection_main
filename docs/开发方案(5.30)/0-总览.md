# 福州地铁接触网智能化检测系统 — 技术开发方案（总览）

> 版本：v2.0 | 编制日期：2026-05-30

---

## 一、方案概述

本方案依据甲方《可行性研究报告 v1.6/v1.8》《软件功能清单及各项参数标准（4）》《附件-1ver02（SRS）》《地铁接触网智能化检测系统产品设计文档（5.18）》及《模糊需求开发技术交流》答复，对系统进行工程化落地设计。全套方案拆分为以下分册：

| 分册 | 内容 | 负责团队 |
|------|------|--------|
| [**1-前端开发方案**](1-前端开发方案.md) | Vue3 + Electron 技术栈、Monorepo 结构、图像渲染、离线方案 | 前端 |
| [**2-后端开发方案**](2-后端开发方案.md) | 地面端微服务 + 车载端单体，数据模型、部署 | 后端 |
| [**3-深度学习接口方案**](3-深度学习接口方案.md) | FastAPI 推理服务约定、模型调度、SLA、模型版本管理 | DL 团队 |
| [**4-接口规范标准**](4-接口规范标准.md) | **三方统一接口契约**（前端↔后端↔DL）、数据字典、状态机、联调约定 | 前端 + 后端 + DL |

前端 + 后端（含调用 DL 的接口层）。DL 团队负责模型训练与 FastAPI 推理引擎，按《4-接口规范标准》对齐。

## 二、系统整体架构

```
┌──────────────────────────────────────────────────────────────┐
│                       应用层 (前端)                            │
│  ┌──────────────────────┐      ┌──────────────────────┐      │
│  │ 车载分析软件          │      │ 地面分析软件          │      │
│  │ Electron + Vue3       │      │ Web Browser + Vue3    │      │
│  │ (打包为便携版 EXE)     │      │ (Nginx 部署 B/S)      │      │
│  └──────────┬───────────┘      └──────────┬───────────┘      │
├─────────────┼─────────────────────────────┼───────────────────┤
│             │          网络层             │                   │
│             │  HTTPS / WSS / RESTful       │                   │
├─────────────┼─────────────────────────────┼───────────────────┤
│             │       业务服务层 (后端)       │                   │
│  ┌──────────┴──────────┐      ┌──────────┴──────────────────┐ │
│  │ 车载端后端【单体架构】 │      │ 地面端后端【微服务架构】       │ │
│  │ inspection-onboard-   │      │ inspection-ground-server     │ │
│  │ server (单 JAR 内嵌    │      │ Gateway + 任务/数据/缺陷/AI   │ │
│  │ 全部模块)             │      │ 调度/鉴权/报表 多服务         │ │
│  └──────────┬──────────┘      └──────────┬──────────────────┘ │
├─────────────┼─────────────────────────────┼───────────────────┤
│             │          核心算法层          │                   │
│  ┌──────────┴──────────┐      ┌──────────┴──────────────────┐ │
│  │ FastAPI 轻量推理      │      │ FastAPI 高性能推理            │ │
│  │ (单 RTX 4090)        │      │ (多 RTX 4090 GPU 集群)        │ │
│  └─────────────────────┘      └─────────────────────────────┘ │
├──────────────────────────────────────────────────────────────┤
│                       基础设施层                               │
│  车载端：单机 MySQL / Redis / MinIO（本地，离线运行）          │
│  地面端：MySQL 主从 / Redis 哨兵 / MinIO 集群 / Nginx / Docker │
└──────────────────────────────────────────────────────────────┘
```

> **关键设计：后端是两个独立可交付的项目**——地面端走微服务（可水平扩展、集群高可用），车载端走单体（单 JAR、零外部依赖、完全离线）。两者**共享同一套数据模型与接口契约**（见《4-接口规范标准》），保证缺陷/任务数据在双端拷贝同步时语义一致。

## 四、双端部署架构

```
  ┌─── 车载端 (检测工程车)   ───┐            ┌─── 地面端 (运维中心)   ───┐
  │                            │            │                          │
  │  Electron 壳 + Vue3 前端    │           │  Nginx → Vue3 前端        │
  │  单体后端 (单 JAR)          │  移动硬盘  │  微服务后端 + Gateway     │
  │  MySQL (本地单机)          │  拷贝 /     │  MySQL 主从              │
  │  Redis (本地单机)          │  网络映射   │  Redis 哨兵集群           │
  │  MinIO (本地单机)          │  同步导入   │  MinIO 分布式集群         │
  │  轻量 AI 模型 (1×4090)     │ ────────►  │  完整 AI 模型 (多×4090)   │
  │  完全离线运行               │             │  集群/单机两种部署        │
  └────────────────────────────┘            └──────────────────────────┘
```

- **车载端**：Windows 10/11 专业版工控机，完全离线，本地数据保留 7 天，磁盘不足时由采集软件滚动删除最早数据。
- **地面端**：支持单机部署（工区级，日任务 ≤10 个）与集群部署（路局级，7×24）两种模式。
- **数据交接**：以移动硬盘拷贝数据包为主，网络映射上传为辅；导入时按「时间戳优先」策略合并，详见《2-后端开发方案》第 6 章。

## 五、分册阅读指引

1. **《4-接口规范标准》是三方协作的唯一权威契约**，任何接口变更先改此文档再落地代码。
2. 前端团队：读《1-前端开发方案》了解结构与交互，按《4》对接后端。
3. 后端团队：读《2-后端开发方案》，注意**地面/车载是两个工程**，按《4》对前端与 DL 暴露契约。
4. DL 团队：读《3-深度学习接口方案》+《4》第 4 章，对齐推理接口、缺陷字典与 SLA。

> 接口对齐规则：前端与后端使用《4》定义的统一 JSON Schema 与错误码；后端与 DL 使用《4》第 4 章定义的 Python 侧推理契约。
