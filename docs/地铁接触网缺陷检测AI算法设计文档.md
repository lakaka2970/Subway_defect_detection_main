## 1. 项目概述与需求指标

## 2. 基础模型选型与规模评估

### 2.1 模型选择：YOLO11

**选型理由：**

- YOLO11 社区资料丰富，部署方案成熟（TensorRT、ONNX 均有完善支持）
- P3-P5 三尺度检测头，小目标检测能力经过广泛验证
- nano/s/m/l/x 五档规模覆盖从轻量到高精度的完整需求
- C2PSA 位置敏感注意力已内建于 backbone 尾部

#### 车载端 m 规模可行性分析

若 YOLO11m FP16 在单卡上达不到 10s 要求，有以下优化路径：

| 手段 | 原理 | 预期收益 | 代价 |
|------|------|----------|------|
| TensorRT INT8 量化 | FP32→INT8，理论吞吐翻倍 | 单切片 50ms→25~30ms | 需校准数据集，精度降 0.5-2% |

**INT8 量化后的关键决策：** m-INT8 精度是否仍显著优于 s-FP16？需通过车载端验证矩阵（见第 9 章）实测决定。

### 3.2 改造①：P3 检测分支 — EMA 替换 ECA

#### 设计原理

小目标（螺栓、开口销，约 8×8 ~ 20×20 px）的检测性能 80% 取决于 P3 分支（8× 下采样，特征图 128×128 @ 1024 输入）。每个特征点覆盖 8×8 像素的感受野——刚好对应一个螺栓的尺度。

#### 为什么是 EMA？

| 对比维度 | ECA（当前） | EMA（替换） |
|----------|------------|------------|
| 空间信息 | GlobalAvgPool → 全部压缩 | X方向 + Y方向 分别编码 |
| 通道交互 | 1D Conv(k=3) 局部交互 | 跨组 1×1 Conv 全交互 |
| 小目标友好度 | 低（空间信息丢失） | 高（保留坐标线索） |
| 参数量 | ~100 | ~200 |
| 延迟增量 | ~0.3ms | ~0.4ms |

**关键优势**：EMA 的 X/Y 双方向池化保留了水平和垂直方向的空间编码——对接触网结构特别有效：X 方向捕获横梁/腕臂的周期结构，Y 方向捕获悬挂/吊柱的垂直结构。

**参考论文**：EMA: Efficient Multi-Scale Attention (ICASSP 2023)

#### 实现要点

```python

    3. 跨组 1×1 Conv 交互

        self.conv1x1 = nn.Conv2d(channels, channels, 1)
        self.conv3x3 = nn.Conv2d(channels, channels, 3, padding=1)
        
        self.sigmoid = nn.Sigmoid()
```

### 3.3 改造②：P4/P5 检测分支 — SimAM 空间注意力

#### 设计原理

SimAM 基于神经科学"空间抑制"理论：视觉皮层中重要的神经元会对周围神经元产生抑制。通过计算每个位置的能量函数 `e = 4(σ²+λ) / ((t-μ)² + 2σ²+2λ)`，找到"与其邻域显著不同的特征点"。

#### 为什么是 SimAM？

| 候选方案 | 参数量 | 小目标增益 | 推理开销 | 选择 |
|----------|--------|-----------|----------|------|
| **SimAM** | **0** | 高（对局部异常敏感） | **~0.1ms** | ✅ |
| CBAM | ~1000 | 中（池化损失细节） | ~2ms | ❌ |
| SE | ~2000 | 低（仅通道维） | ~1ms | ❌ |
| CA | ~500 | 高（保留坐标） | ~1ms | 备选 |

**关键优势**：零参数 → 零过拟合风险，在有限标注数据（500 张）下尤其关键。

"螺栓缺失"本质是局部异常——应该有个螺栓的位置出现了空洞。SimAM 的能量函数天然对"局部出现与周围不一致的特征"敏感。

**参考论文**：SimAM: A Simple, Parameter-Free Attention Module (ICML 2021)

#### 实现要点

```python
class SimAM(nn.Module):
    """
    Simple, Parameter-Free Attention Module.
    
    能量函数: e = 4 * (sigma^2 + lambda) / ((t - mu)^2 + 2*sigma^2 + 2*lambda)
    其中 t 是目标神经元, mu/sigma 是邻域均值和方差, lambda=1e-4
    
    输出: 1 / (1 + e) 作为注意力权重
    """
    def __init__(self, lambda_e=1e-4):
        super().__init__()
        self.lambda_e = lambda_e
    
    def forward(self, x):
        # 计算每个空间位置的均值
        mu = x.mean(dim=[2, 3], keepdim=True)
        # 计算每个空间位置的方差
        sigma = ((x - mu) ** 2).mean(dim=[2, 3], keepdim=True)
        # 能量函数
        e = 4 * (sigma + self.lambda_e) / (
            (x - mu) ** 2 + 2 * sigma + 2 * self.lambda_e
        )
        # 注意力权重
        attention = 1 / (1 + e)
        return x * attention
```

## 4. 双卡异构 Ensemble（地面端）

### 4.1 方案选型

地面端采用**方案B：异构双卡 Ensemble**，两张卡运行结构差异化的模型，通过 WBF（Weighted Boxes Fusion）融合结果，利用两个模型不同的错误模式来压制提报率。

### 4.2 架构设计

```
│                                                          │
│  输入图像 → 切片引擎 → 200个切片（两份副本）                 │
│                                                          │
│  ┌────────────────────────┐  ┌────────────────────────┐  │
│  │  GPU 0: YOLO11m-ECA    │  │  GPU 1: YOLO11m-P2    │  │
│  │  (ECA注意力增强)        │  │  (P2四尺度小目标特化)    │  │
│  │  侧重：全局特征建模      │  │  侧重：极小目标捕获      │  │
│  │  200切片的检测框A       │  │  200切片的检测框B       │  │
```

### 4.3 WBF 融合机制

#### 核心参数

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| WBF IoU 阈值 | 0.55 | 判断两个框是否指向同一目标 |
| 双模型置信阈值 | 0.25 / 0.20 | 各自独立推理时用较低阈值，保留更多候选 |
| **单模型采信阈值** | **0.75** | 只有一个模型检出的框，需 conf≥0.75 才采信 |
| **双模型采信阈值** | **0.50** | 两个模型都检出的框，平均 conf≥0.50 即采信 |
| 融合后总阈值 | 0.60 | 最终输出阈值 |

#### 采信规则

```
is_valid = (both_detected AND avg_conf ≥ 0.50) 
        OR (single_detected AND conf ≥ 0.75)
```

**设计原理**：两个独立训练的模型在相同噪声位置同时误报的概率极低，而真实缺陷两个模型都有较高置信度。单模型误报（孤立高置信度框）会被更高的阈值过滤。

#### 融合流程

```
假设同一位置（螺栓区域）两个模型都给出了检测：

模型A (YOLO11m-ECA):  box=[0.342, 0.561, 0.012, 0.009], conf=0.92
模型B (YOLO11m-P2):  box=[0.343, 0.560, 0.013, 0.008], conf=0.88

Step 1: IoU匹配 → IoU=0.62 > 0.55 → 判定为同一目标
Step 2: 加权融合 → 
  fused_conf = (0.92 + 0.88) / 2 = 0.90
  fused_box  = 按 conf 加权平均坐标
Step 3: fused_conf=0.90 > 0.50 → 输出

---

单一模型误报（反光噪声区域）：

模型A: box=[0.678, 0.234, 0.008, 0.006], conf=0.61
模型B: 无检测

Step 1: 无匹配框
Step 2: 单模型检测 → conf=0.61
Step 3: 0.61 < 0.75（单模型采信阈值） → 过滤！

→ 孤立误报被压制 ✓
```

### 4.4 异构互补性分析

| 互补维度 | GPU 0 (ECA版) | GPU 1 (P2版) |
|----------|---------------|--------------|
| 注意力机制 | ECA 通道选择 | P2 空间尺度扩展 |
| 小目标敏感度 | 中（3尺度） | 高（4尺度，P2层256×256） |
| 易误报场景 | 结构纹理误判 | 小噪点误判 |
| 错误模式相关性 | — | **低**（ECA 和 P2 的错误来源不重叠） |

两个模型的"盲区"和"误报偏好"不同 → WBF 融合后提报率从单模型 ~8-10% 降至 ~3-5%。

## 5. 高像素切片推理管道

### 5.1 问题定量化

```
127MP 图像参数: ~13000 × 9800 像素

均匀切片（SAHI 基线）:
├─ 切片尺寸: 1024×1024
├─ 重叠率: 15%
├─ 有效步长: 870px
├─ 水平切片数: ceil(13000/870) ≈ 15
├─ 垂直切片数: ceil(9800/870) ≈ 12
├─ 总切片数: ≈ 180 片
│
├─ 每片预处理(加载+缩放+归一化): ~8ms
├─ YOLO11s 推理: ~25ms
├─ 每片后处理(NMS+坐标映射): ~3ms
├─ 串行总耗时: 180×(8+25+3) = 6,480ms (仅理想推理)
│
└─ 额外开销:
    ├─ 127MP JPEG 解码: ~2.5s (CPU)
    ├─ 大图裁切: ~1s (CPU)
    └─ 全局合并 NMS: ~1s
    ─────────────────────
    总耗时: ~11s ← 超出 10s 限制
```

**核心矛盾**：180 个切片中 60-70% 不包含接触网结构（天空、隧道壁、地面），但全被送进模型。

### 5.3 Stage 1: ROI 提案器设计

#### 为什么检测"结构元素"而非直接降采样检测缺陷

降采样到 1/8 后，一个 8×8 px 的螺栓变成 1×1 px——完全不可见。但"螺栓群所在的安装底座区域"（~200×150 px 原始 → ~25×19 px 降采样后）仍然清晰可辨。

```
Stage 1 检测目标（降采样后仍可见）:

  bolt_region:       螺栓群区域         (~40×40 px 在 1/8 尺度)
                      包含多个螺栓的安装底座
                      
  joint_region:      接头区域           (~60×30 px 在 1/8 尺度)
                      汇流排中间接头、膨胀接头
                      
  insulator_region:  绝缘子区域          (~80×60 px 在 1/8 尺度)
                      
  support_region:    支撑/悬挂区域       (~50×50 px 在 1/8 尺度)
                      腕臂底座、吊柱顶板

Stage 2 在 ROI 内部检测（全分辨率，1024 切片）:
  螺母缺失、螺栓松动、开口销缺失等细粒度缺陷
```

#### ROI 提案器关键设计

- **模型**：YOLO11n（轻量，保证提案速度）
- **置信阈值**：0.10-0.15（极低——宁可多报 100 个假 ROI，绝不漏报 1 个真实结构区域）
- **标注成本**：低（结构区域大，标注容易，~1000 张即可满足训练）
- **阶段分离**：ROI 提案器和缺陷检测器完全独立，互不影响

### 5.5 CUDA Stream 三阶段流水线

```
时序图（流水线重叠优化）：

Stream 1 (CPU):  │ 加载切片N │ 预处理N  │         │ 后处理N │ 加载N+1│ ...
Stream 2 (GPU):  │          │ 推理N-1  │ 推理N   │         │ 推理N+1│ ...
Stream 3 (CPU):  │          │          │ 合并N-2 │         │        │ ...
                 └──────────────────────────────────────────────────────
                 时间轴 →

效果: 预处理和推理时间重叠, 实际总耗时 ≈ max(预处理, 推理) + 少量固定延迟
      而非 预处理+推理+后处理 的简单相加

附加优化:
  - nvJPEG GPU 加速解码，减少 CPU 瓶颈
  - 固定分辨率切片预分配 GPU 内存池，避免动态分配
  - TensorRT 构建时使用 CUDA Graph 消除 kernel launch overhead
```

### 7.2 主动学习策略

```
当前状态: 500张, 类别不全
目标:    逐步扩充到 ~3000+ 张, 覆盖全部类别

主动学习筛选逻辑:

1. 不确定性采样 (Uncertainty Sampling):
   - 对车载采集的无标注图像做推理
   - 筛选 conf ∈ [0.3, 0.6] 的检测 (模型不确定的)
   - 这些样本对模型决策边界影响最大, 标注优先级高

2. 多样性采样 (Diversity Sampling):
   - 对不确定样本做特征聚类 (使用 backbone 输出的特征向量)
   - 从每个聚类中均匀采样 → 避免标注高度相似图像

3. 类别补齐 (Class Balancing):
   - 统计当前数据集中各类别的实例数
   - 优先寻找缺失/稀疏类别的图像
   - 目标: 每类至少 100 个实例

4. 困难样本挖掘 (Hard Example Mining):
   - 线上推理中模型与人工审核不一致的样本
   - 自动收集为"困难样本", 加入下一轮训练

执行周期:
  - 前 3 个月: 月循环 (快速补齐类别和场景)
  - 稳定后:    季度循环 (维护性重训练)
```

## 8. 损失函数与评估指标

### 8.1 损失函数设计

#### YOLO11 默认损失

```
L = λ_box × CIoU_loss  +  λ_cls × BCE_loss  +  λ_dfl × DFL_loss
     ↑ 框回归             ↑ 分类              ↑ 分布焦点损失
```

#### 针对接触网小目标场景的调整

```python
# 调整①: CIoU → Wise-IoU (WIoU)
"""
Wise-IoU 对极小框的梯度更稳定，不会因 IoU=0 时梯度消失。
当检测框与标注框完全不重叠时，CIoU 梯度为 0，WIoU 仍能提供有意义的梯度信号。

参考: Wise-IoU: Bounding Box Regression Loss with Dynamic Focusing (2023)
"""

# 调整②: 类别不平衡权重
class_weights = {
    # 主要缺陷 (数据充足)
    "rigid_base_nut_missing":      1.0,
    "rigid_base_nut_loose":        1.0,
    
    # 次要缺陷 (样本较少, 更难检测)
    "rigid_ground_wire_nut_missing": 1.2,
    "rigid_ground_wire_nut_loose":   1.2,
    "rigid_single_bracket_base_nut_missing": 1.15,
    
    # 罕见/困难类别
    "rigid_insulator_damage":      1.5,
    "foreign_object":              1.5,
    "flex_dropper_no_force":       1.3,
}

# 调整③: Focal Loss 替代标准 BCE (分类分支)
"""
α=0.25, γ=2.0
对于极端不平衡的缺陷/背景比例:
  - 单张图可能只有 2-3 个缺陷 vs 数千个负样本位置
  - Focal Loss 自动降低易分类负样本的权重
"""
```

#### 完整损失函数

```
L_total = 1.5 × WIoU_loss(box)            # 框回归 (权重最高, 小目标定位关键)
        + 0.5 × FocalLoss(cls, α=0.25, γ=2.0)  # 分类 (Focal处理类别不平衡)
        + 1.5 × DFL_loss(dfe)             # 分布焦点损失
        × class_weight[cls]               # 类别权重
```

### 8.2 评估指标

#### 核心验收指标

| 指标 | 公式 | 车载目标 | 地面目标 |
|------|------|----------|----------|
| Recall (检出率) | TP / (TP + FN) | ≥ 90% | ≥ 90% |
| Precision (准确率) | TP / (TP + FP) | ≥ 90% | ≥ 90% |
| F1 Score | 2PR / (P+R) | ≥ 0.90 | ≥ 0.90 |
| 提报率 | 检出缺陷图片数 / 总图片数 | — | ≤ 5% |
| 单图推理时间 | 端到端 | ≤ 10s | — |
| 模型加载时间 | 启动到可用 | ≤ 1s | ≤ 2s |

#### 训练监控指标

| 指标 | 说明 |
|------|------|
| mAP@0.5 | 各类别平均精度的 IoU=0.5 下的值 |
| mAP@0.5:0.95 | 严格的多 IoU 阈值评估 |
| Per-class Recall | 每个缺陷类别的召回率, 监视类别退化 |
| Per-class Precision | 每个缺陷类别的准确率 |
| Confusion Matrix | 类别间混淆情况 |

#### 评估协议

```
测试集分割:
  - 预留 20% 数据作为 holdout test set (不参与训练)
  - 5-fold cross-validation 交叉验证 (500张数据有限时的必要手段)

评估流程:
  1. 每 epoch 结束后在 val set 上评估
  2. 训练结束后在 holdout test set 上评估
  3. 每类缺陷分别计算 Recall/Precision
  4. 汇总计算加权平均

验收测试集要求:
  - 覆盖全部缺陷类别
  - 覆盖隧道/露天两种场景
  - 包含边界情况: 强反光、部分遮挡、模糊
```

## 9. 车载端验证矩阵与选型决策

### 9.1 验证矩阵

车载端需要在这个矩阵上进行全面实测，基于实测数据做出最终选型决策：

```
┌──────────────────┬──────────────┬──────────────┬──────────────┐
│                  │  FP16        │  INT8        │  FP16        │
│                  │  1024切片     │  1024切片     │  1280切片     │
├──────────────────┼──────────────┼──────────────┼──────────────┤
│  YOLO11s-EMA     │  ✓ 必测       │  ✓ 选测       │  ✓ 选测       │
│  -SimAM          │              │              │              │
├──────────────────┼──────────────┼──────────────┼──────────────┤
│  YOLO11m-EMA     │  ✓ 必测       │  ✓ 必测       │  ✓ 选测       │
│  -SimAM          │              │              │              │
└──────────────────┴──────────────┴──────────────┴──────────────┘

每个格子需测量的指标:
  ├─ Recall (total + per-class)
  ├─ Precision (total + per-class)
  ├─ F1 Score
  ├─ 端到端推理耗时 (含图像解码+切片+推理+NMS)
  ├─ GPU 显存占用
  └─ 模型加载时间
```

### 9.2 决策逻辑

```
决策优先顺序:

Step 1 — 精度筛选:
  过滤掉 Recall < 90% 或 Precision < 90% 的组合

Step 2 — 速度筛选:
  在满足精度的组合中, 选总耗时 ≤ 10s 的

Step 3 — 最优选择:
  ┌─────────────────────────────────────────────────┐
  │ 情况A: 多个组合都满足 → 选方案最简单的 (s-FP16)    │
  │        理由: FP16 无需量化校准, 部署风险最低       │
  │                                                  │
  │ 情况B: s-FP16 精度不够, m-INT8 满足 → 选 m-INT8  │
  │        理由: 量化虽增工程复杂度, 但精度达标         │
  │                                                  │
  │ 情况C: 仅 s-FP16 满足 → 车载 s, 地面 m            │
  │        理由: 车载"够用就好", 地面用更大模型抓精度   │
  │                                                  │
  │ 情况D: 全都达不到 → 启动方案C (先验引导自适应切片) │
  │        理由: 必须进一步减少切片数才能达标           │
  └─────────────────────────────────────────────────┘
```

### 9.3 INT8 量化验证流程

```
1. 校准数据集准备:
   - 从训练集中随机抽取 200-500 张代表性图像
   - 覆盖典型场景: 隧道、露天、不同光照

2. TensorRT INT8 校准:
   builder.int8_mode = True
   builder.int8_calibrator = EntropyCalibrator2(calibration_data)
   → 构建 INT8 engine

3. 精度对比:
   在同一测试集上对比 FP16 vs INT8:
   - mAP 下降 ≤ 2% → INT8 可用
   - mAP 下降 > 2% → 需要评估是否仍满足 ≥90%
```

| INT8量化后精度下降>2% | 车载端m模型不可用 | 低 | 回退方案: s-FP16依然达标的可能性很高 |
| 两级管道Stage1漏检 | 缺陷漏检 | 低 | ROI阈值设极低(0.10)，Recall≥99%硬约束 |
| 新缺陷类别长时间无法采集 | 类别缺失 | 中 | 合成数据(CG渲染+Inpainting)过渡 |
| 推理耗时>10s | 验收失败 | 低 | INT8+大切片+CUDA Stream三重优化 |
| 车载端模型加载>1s | 验收失败 | 极低 | TensorRT engine预序列化+内存预热 |

### 10.4 需要确认的开放问题

1. **训练数据路径**：当前 500 张数据的具体存储位置和标注格式
2. **无缺陷图像**：是否有大量无缺陷接触网图像可采集？训练需要负样本
3. **相机参数**：每个相机位采集的图像分辨率和视野范围，用于调整切片策略
4. **缺陷标注标准**："螺母松动"的判定标准（松动多少算缺陷？），避免标注歧义
5. **提报率定义确认**：提报率 = 检出缺陷的图片数 / 总图片数，这个计算口径是否正确？
