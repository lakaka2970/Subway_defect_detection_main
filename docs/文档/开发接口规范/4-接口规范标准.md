# 4 — 接口规范标准（前端 ↔ 后端 ↔ 深度学习 三方统一契约）

> 版本：v1.0 | 编制日期：2026-05-30
> **本文档是三个团队协作的唯一权威接口契约**。任何接口/字段/枚举变更，先改本文档并经三方确认，再落地代码。
>
> 适用团队：前端（Vue3/Electron）、后端（地面微服务 + 车载单体）、深度学习（FastAPI）。

---

## 1. 协作边界与契约分层

```
┌─────────┐   契约 A：REST + WebSocket   ┌──────────────────┐  契约 B：REST  ┌─────────┐
│  前端    │ ───────────────────────────► │  后端             │ ─────────────► │  DL      │
│ Vue3 /   │ ◄─────────────────────────── │ 地面微服务 /       │ ◄───────────── │ FastAPI  │
│ Electron │      统一响应 + 错误码        │ 车载单体（同契约） │   推理结果      │          │
└─────────┘                              └──────────────────┘                └─────────┘
```

- **契约 A（前端↔后端）**：本文档第 3、5、6 章。前端不直接访问 DL。
- **契约 B（后端↔DL）**：本文档第 4 章 +《3-深度学习接口方案》。
- **数据字典（第 7 章）**：三方共用的缺陷编码、枚举、状态机，是契约一致性的根基。
- **双端一致性**：地面端（微服务）与车载端（单体）对前端暴露**完全相同的契约 A**，前端代码无需区分两端（仅 `baseURL` 不同）。

## 2. 通用约定（契约 A 全局）

### 2.1 基础规范

| 项 | 约定 |
|----|------|
| 基础路径 | `/api/v1/` |
| 传输协议 | 地面 HTTPS / WSS；车载本地 HTTP（`localhost`） |
| 请求/响应体 | `application/json; charset=utf-8` |
| 文件上传 | `multipart/form-data` |
| 文件下载 | `application/octet-stream`（报表/数据包流） |
| 时间格式 | ISO 8601：`2026-05-30T22:10:00+08:00` |
| 字符编码 | UTF-8 |
| ID 类型 | 字符串（前端统一按 string 处理，避免 JS 大整数精度问题） |

### 2.2 统一响应格式

成功：

```json
{
  "code": 200,
  "data": { },
  "message": "success",
  "requestId": "a1b2c3d4-..."
}
```

失败：

```json
{
  "code": "400-T001",
  "data": null,
  "message": "任务名称不能为空",
  "requestId": "a1b2c3d4-..."
}
```

> 前端拦截器：`code` 为成功码（`200`/`0`）时解包返回 `data`；否则按 `code` 走错误映射（详见 2.4）。

### 2.3 分页约定

请求（query）：`pageNum`（从 1 起）、`pageSize`（默认 50）、`sortField`、`sortOrder`（`asc|desc`）。

响应 `data`：

```json
{
  "list": [ ],
  "total": 12345,
  "pageNum": 1,
  "pageSize": 50
}
```

### 2.4 错误码规范

格式：`HTTP状态码-模块标识+三位数字`，例：`400-T001`。

| 模块标识 | 含义 |
|----------|------|
| `A` | 鉴权 Auth |
| `T` | 任务 Task |
| `R` | 原始数据 RawData |
| `D` | 缺陷 Defect |
| `AI` | AI 分析调度 |
| `RP` | 报表 Report |
| `S` | 系统/基础数据 System |
| `SY` | 同步 Sync |

常用错误码（前端做用户提示映射）：

| code | 提示文案 |
|------|----------|
| `401-A001` | 登录已过期，请重新登录 |
| `403-A002` | 您没有该操作的权限 |
| `400-T001` | 任务参数校验失败 |
| `409-R001` | 原始数据不存在或已删除 |
| `500-AI001` | AI 分析服务暂不可用，请稍后重试 |
| `507-AI002` | AI 显存不足，已自动降级重试 |

### 2.5 鉴权

- 登录返回 `accessToken`，前端存 `localStorage`，每次请求头携带 `Authorization: Bearer {token}`。
- WebSocket 通过 URL query 携带 `?token={token}`。
- 后端用 Sa-Token 校验；权限标识见第 7.5 节。

### 2.6 坐标系约定（三方必须一致）

缺陷框统一采用**归一化中心点 + 宽高**（与 YOLO 一致），取值 0~1：

```json
"box": { "x": 0.3421, "y": 0.5612, "w": 0.0123, "h": 0.0089 }
"coordType": "normalized"   // 或 "pixel"（像素坐标，需附图宽高）
```

- DL 推理默认输出 `normalized`；后端入库存归一化值（`t_defect.box_x/y/w/h`、`box_coord_type`）。
- 前端 fabric.js 渲染时按当前图像宽高换算为像素：`px = x * imageWidth`。

## 3. 契约 A：前端 ↔ 后端 接口清单

> 与前端 `packages/shared/src/api/modules/*` 一一对应。地面/车载暴露相同路径，车载端对未实现的能力返回 `501`。

### 3.1 鉴权 `/auth`（authApi）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/login` | 登录 `{username,password}` → `{accessToken,userInfo}` |
| POST | `/auth/logout` | 登出 |
| GET | `/auth/userInfo` | 当前用户信息 + 角色 + 权限标识数组 |

### 3.2 任务管理 `/task`（taskApi）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/task/create` | 创建任务 |
| POST | `/task/import` | 从 index 文件批量导入 |
| GET | `/task/list` | 分页查询（线路/状态/时间筛选） |
| GET | `/task/{id}` | 任务详情（含子任务进度分解） |
| PUT | `/task/{id}/status` | 更新任务状态 |
| DELETE | `/task/{id}` | 软删除 |

### 3.3 原始数据 `/rawData`（rawDataApi）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/rawData/upload` | 批量上传数据包（multipart） |
| GET | `/rawData/list` | 多条件分页查询 |
| GET | `/rawData/{id}` | 详情（含几何参数/定位信息） |
| GET | `/rawData/{id}/filePath` | 返回物理路径（前端「打开文件路径」） |
| POST | `/rawData/{id}/startAnalysis` | 对该数据发起 AI 分析 |
| POST | `/rawData/sync` | 触发数据同步 |
| DELETE | `/rawData/{id}` | 软删除 |

### 3.4 缺陷管理 `/defect`（defectApi）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/defect/list` | 多条件分页查询 |
| GET | `/defect/pillars` | 按任务返回区站-支柱树（缩略图 8 维筛选） |
| GET | `/defect/statistics` | 按维度统计（柱状/饼/环图数据） |
| GET | `/defect/{id}` | 缺陷详情 |
| PUT | `/defect/{id}/status` | 状态流转（含三态裁决） |
| POST | `/defect/manual` | 人工新增缺陷标注 |
| PUT | `/defect/{id}/annotation` | 编辑标注框 |
| DELETE | `/defect/{id}` | 删除 |
| POST | `/defect/template/import` | 导入标准缺陷模板 |

缺陷对象（响应 `data` 示例）：

```json
{
  "id": "10086",
  "defectCode": "DF-20260530-0001",
  "taskId": "2001",
  "rawDataId": "30021",
  "defectType": "rigid_ground_wire_nut_missing",
  "defectName": "地线线夹螺母缺失",
  "defectLevel": "serious",
  "confidence": 0.923,
  "box": { "x": 0.3421, "y": 0.5612, "w": 0.0123, "h": 0.0089 },
  "coordType": "normalized",
  "lineName": "2号线",
  "stationArea": "鼓山-南门兜",
  "pillarCode": "P125",
  "kilometerMark": "K22+494",
  "bridgeTunnel": "",
  "frameNo": 23,
  "workArea": "福州供电工区",
  "status": "detected",
  "detectedBy": "AI",
  "source": "onboard",
  "analyst": "张三",
  "analysisTime": "2026-05-30T20:10:00+08:00"
}
```

### 3.5 AI 分析调度 `/aiTask`（aiTaskApi）

| 方法 | 路径 | 请求 → 响应 |
|------|------|-------------|
| POST | `/aiTask/start` | `{taskId}` → `{analysisId}` |
| PUT | `/aiTask/control` | `{analysisId, controlType: pause\|resume\|cancel}` → null |
| GET | `/aiTask/progress/{analysisId}` | → `AnalysisProgress`（WS 降级用） |

### 3.6 报表统计 `/report`（reportApi）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/report/preview` | 预览报表数据 |
| GET | `/report/export` | 导出 `format=excel\|word\|pdf`（Word=缺陷治理建议书，含标注图） |
| GET | `/report/template/list` | 报表模板列表 |
| POST | `/report/template` | 保存自定义模板（DIY 列/顺序/筛选） |

### 3.7 系统管理 `/system`（systemApi）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET/PUT | `/system/config` | 系统设置（双屏/记忆支柱区域等开关） |
| POST/PUT/DELETE | `/system/vehicle[/{id}]` | 检测车基础数据 |
| POST/PUT/DELETE | `/system/line[/{id}]` | 线路基础数据 |

### 3.8 WebSocket：分析进度推送

- 地址：`wss://{host}/api/v1/ws/analysis/{analysisId}?token={token}`
- 服务端推送消息体：

```json
{
  "type": "progress",
  "payload": {
    "taskId": "2001",
    "analysisId": "an-9988",
    "processedCount": 3421,
    "totalCount": 10000,
    "defectCount": 47,
    "currentStage": "processing",
    "stageDetail": "AI识别中：正在处理第 3421/10000 张"
  }
}
```

- `currentStage` 枚举：`idle | loading | processing | completed | paused | error`
- **断线降级**：WS 断开后前端切 HTTP 轮询 `GET /aiTask/progress/{analysisId}`（每 5s），恢复后切回。

## 4. 契约 B：后端 ↔ 深度学习（FastAPI）

> 详见《3-深度学习接口方案》；此处为三方对齐要点与字段映射，DL 团队以此交付。

### 4.1 接口清单

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/dl/health` | 健康检查 + 已加载模型 + GPU 状态 |
| POST | `/api/dl/model/load` | 加载模型 `{modelType, modelVersion, forceReload}` |
| POST | `/api/dl/infer` | 单图推理（核心） |
| POST | `/api/dl/infer/batch` | 批量推理（地面端） |

### 4.2 推理请求/响应（核心字段）

请求关键字段：`imagePath`、`modelType`(`onboard\|ground`)、`confidenceThreshold`、`outputCoordType`、`extraParams.{sliceSize,sliceOverlap,highResRegions}`。

响应关键字段：`defects[].{defectType, defectName, confidence, box{x,y,w,h}, coordType, sourceSlice}`。

### 4.3 后端 → 缺陷库 字段映射（DL 必须遵守第 7.1 字典）

| DL 输出字段 | 后端入库字段 `t_defect` |
|-------------|--------------------------|
| `defectType` | `defect_type`（必须是第 7.1 节编码之一） |
| `confidence` | `confidence` |
| `box.x/y/w/h` | `box_x/box_y/box_w/box_h` |
| `coordType` | `box_coord_type` |
| （由字典查得）严重等级 | `defect_level` |

### 4.4 错误码与容错

DL 错误码：`DL_MODEL_NOT_LOADED(503)`、`DL_GPU_OOM(507)`、`DL_IMAGE_UNREADABLE(400)`、`DL_INFERENCE_TIMEOUT(504)`、`DL_INTERNAL_ERROR(500)`。后端容错：自动加载重试、降切片重试、超时跳过（标记 `skipped`）。

## 5. 数据字典与枚举（三方共用 — 单一事实来源）

### 5.1 缺陷类型编码字典（16 种，确认范围）

> DL 训练类别标签、后端 `defect_type`、前端展示均以此为准；新增类型走第 8 章变更流程。

#### 刚性接触网（13 种）

| 编码 | 中文名称 | 严重等级 |
|------|----------|----------|
| `rigid_base_nut_missing` | 垂直悬吊安装底座螺母缺失 | serious |
| `rigid_base_nut_loose` | 垂直悬吊安装底座螺母松动 | serious |
| `rigid_single_bracket_base_nut_missing` | 单支垂直悬吊槽钢底座螺母缺失 | serious |
| `rigid_single_bracket_base_nut_loose` | 单支垂直悬吊槽钢底座螺母松动 | serious |
| `rigid_single_bracket_upper_nut_loose` | 单支垂直悬吊槽钢上方螺母松动 | normal |
| `rigid_hanger_top_plate_nut_missing` | 刚性悬挂吊柱顶板底面螺母缺失 | serious |
| `rigid_hanger_top_plate_nut_loose` | 刚性悬挂吊柱顶板底面螺母松动 | serious |
| `rigid_ground_wire_clamp_nut_missing` | 地线线夹托板安装底座螺母缺失 | serious |
| `rigid_ground_wire_clamp_nut_loose` | 地线线夹托板安装底座螺母松动 | serious |
| `rigid_ground_wire_nut_missing` | 地线线夹螺母缺失 | serious |
| `rigid_ground_wire_nut_loose` | 地线线夹螺母松动 | serious |
| `rigid_busbar_joint_bolt_missing` | 汇流排中间接头螺栓缺失 | critical |
| `rigid_insulator_damage` | 绝缘子破损 | critical |

#### 柔性接触网（3 种）

| 编码 | 中文名称 | 严重等级 |
|------|----------|----------|
| `flex_wrist_base_hori_pin_missing` | 腕臂底座横向销钉缺开口销 | serious |
| `flex_wrist_base_vert_pin_missing` | 腕臂底座垂直销钉缺开口销 | serious |
| `flex_dropper_no_force` | 吊弦不受力 | serious |

> DL 团队交付 `defect_dict.json`（编码 + 中文 + 严重等级），后端启动时加载校验，确保三方一致。完整字典以甲方最终确认为准。

### 5.2 严重等级 `defectLevel`

`minor`（轻微）/ `normal`（一般）/ `serious`（严重）/ `critical`（紧急）

### 5.3 任务状态机 `task.status`

```
pending（待分析）→ analyzing（分析中）→ completed（已完成）→ reviewed（已复核）→ archived（已归档）
```

### 5.4 缺陷状态机 `defect.status`（含三态裁决）

```
detected（AI检出）→ reviewing（复核中）
   ├─ confirmed（确认）──► repaired（已维修）→ accepted（已验收）→ closed（关闭）
   ├─ observed（待观察）
   └─ rejected（驳回误报，作模型负样本）
```

前端三态裁决按钮 → `PUT /defect/{id}/status`：`confirmed | observed | rejected`。

### 5.5 角色与权限标识（动态 RBAC）

预置 4 角色，其余由管理员自由配置：

| 角色 | 角色码 | 说明 |
|------|--------|------|
| 系统管理员 | `admin` | 全部功能 |
| 复核专家 | `reviewer` | 复核、标注、报表 |
| 普通运维人员 | `operator` | 任务/数据/报表查看 |
| 采集操作员 | `collector` | 任务创建、采集 |

权限标识（前端 `v-has-perm` 控制按钮/菜单）：`task:view/create/delete`、`rawdata:view/upload/delete`、`defect:view/review/edit/delete`、`report:view/export`、`system:config/vehicle/line`。

### 5.6 缩略图筛选 8 维度

`pillarCode`（杆号）、`deviceType`（支柱装置：中间柱/转换柱）、`additionalSuspension`（附加悬挂）、`hangerColumn`（吊柱）、`contactSuspension`（接触悬挂）、`side=front/back`（正面/反面）、`analysisStatus`（分析状态）。

## 6. 双端一致性约定

| 项 | 约定 |
|----|------|
| 契约一致 | 地面（微服务）与车载（单体）对前端暴露**完全相同的契约 A**，前端仅切换 `baseURL` |
| 数据模型一致 | 两端共用 `domain-model`（实体/枚举/字典），缺陷与任务字段语义一致 |
| 数据交接 | 车载导出数据包（含 info.xml）→ 移动硬盘/网络 → 地面导入（`/rawData/upload` 或 `/rawData/sync`） |
| 冲突合并 | 「时间戳优先」：`updated_at` 较新者覆盖，冲突写 `t_sync_conflict_log` |
| 数据粒度 | 统一按「公里标_杆号_缺陷类型」组织（《模糊需求》答复确认） |
| 未实现能力 | 车载端对地面专属能力（完整报表等）返回 `501-XXX`，前端按权限/能力开关隐藏入口 |

## 7. 版本管理与联调约定

### 7.1 版本与兼容

- 接口走 URL 版本：`/api/v1/`。破坏性变更升 `v2`，并行过渡。
- 字段只增不删；废弃字段标注 `@deprecated` 保留一个版本。
- 模型版本号：`{基础模型}-{规模}-v{主}.{次}`（如 `yolov11-s-v1.2`），通过 `modelVersion` 区分。

### 7.2 联调环境与顺序

1. 前端先用本地 Mock（`VITE_USE_MOCK`）按契约 A 自测。
2. 后端提供 Swagger（`/swagger-ui`）与契约 A 一致的桩。
3. 后端↔DL 用固定测试图集联调（见《3》第 9 章 `test-images/` + `expected.json`）。
4. 三方集成：前端连真实后端，后端连真实 DL，跑端到端用例。

### 7.3 联调通过标准

- 契约 A：所有接口字段、错误码、分页与本文档一致；WS 进度可正常推送与降级。
- 契约 B：测试图集全部 HTTP 200，缺陷类型/位置偏差 ≤5% 图宽高，单图耗时满足 SLA。

## 8. 接口变更流程

1. 提出方在本文档对应章节标注变更（红字/批注）。
2. 三方（前端 + 后端 + DL）评审确认，更新数据字典与 Swagger。
3. 后端先发布兼容版本 → 前端/DL 跟进 → 回归联调。
4. 合并本文档版本号并记录变更日志。

> 原则：**契约先行**。先改本文档达成一致，再改代码；禁止「代码先于契约」造成三方不一致。
