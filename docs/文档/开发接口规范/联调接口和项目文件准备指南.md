## 4. 联调前修复项

### 4.1 P0 — 阻塞联调 ✅ 已全部修复

#### 4.1.1 ✅ 修复 API 路径前缀

Health 端点主路径改为 `/api/dl/health`，保留 `/health` 作为兼容旧版的重定向。

**文件**: `subway_defect/deployment/fastapi_server.py`

#### 4.1.2 ✅ 统一字段命名为 camelCase

使用 Pydantic `ConfigDict(populate_by_name=True)` + `Field(alias="camelCase")` 机制，同时兼容 camelCase（规范）和 snake_case（内部）。

涉及模型：`InferRequest`, `InferResponse`, `DefectResult`, `BatchInferRequest`, `BatchInferResponse`, `ModelLoadRequest`, `ModelLoadResponse`, `HealthResponse`

#### 4.1.3 ✅ 统一 model_type 枚举值

车载端标识改为 `"onboard"`（规范定义），同时接受 `"vehicle"` 作为向后兼容别名。CLI `--mode` 参数同步更新。

#### 4.1.4 ✅ 实现标准化错误码

新增 `dl_error_response()` 函数，统一返回规范定义的标准化错误响应：

| 错误码 | HTTP 状态码 | 触发场景 |
|--------|-----------|---------|
| `DL_MODEL_NOT_LOADED` | 503 | 模型未加载时调用推理 |
| `DL_GPU_OOM` | 507 | GPU 显存不足 |
| `DL_IMAGE_UNREADABLE` | 400 | 图像文件不存在或无法解码 |
| `DL_INFERENCE_TIMEOUT` | 504 | 单张推理超过 30 秒 |
| `DL_INTERNAL_ERROR` | 500 | 未预期的内部异常 |

#### 4.1.5 ✅ 添加缺失的响应字段

- `totalSlices`: 在 `TwoStagePipeline.infer()` 返回值中新增，通过 `SmartSlicer.roi_tile_count()` 计算
- `coordType`: 固定返回 `"normalized"`（当前管道始终输出归一化坐标）

#### 4.1.6 ✅ 实现缺陷名称中文映射

`_resolve_defect_name()` 函数：优先从 `defect_dict.json` 查找，fallback 到 `classes.py` 的 `CN_NAME_MAP`，再 fallback 到类编码本身。

### 4.2 P1 — 重要优化 ✅ 已实现

#### 4.2.1 ✅ 创建 `defect_dict.json`

已创建 `subway_defect/deployment/defect_dict.json`，包含：
- 16 个缺陷类型的完整映射（code → name_cn → severity → category）
- 严重等级定义
- 缺陷类别分组

#### 4.2.2 ✅ 实现批量推理接口 `POST /api/dl/infer/batch`

新增 `infer_batch()` 端点，支持地面端批量推理，返回：
- 每张图像独立的推理结果
- 总耗时 / 平均耗时 / 吞吐量统计

#### 4.2.3 ✅ 修复健康检查响应结构

`/api/dl/health` 返回规范定义的 `loadedModels` 数组格式，包含 `modelType`, `version`, `loadedAt`。

#### 4.2.4 ⚠️ `outputCoordType` 支持

请求接受 `outputCoordType` 参数（`"normalized"` 或 `"pixel"`）。当前实现固定返回 `"normalized"` 坐标。`pixel` 坐标模式保留扩展点，需要时在 pipeline 中添加坐标转换逻辑。
